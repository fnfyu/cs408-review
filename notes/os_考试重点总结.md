### 模块：1.1 操作系统的概念与功能

#### 1.1.1 操作系统的概念 【熟练掌握】

#### 定义
- 操作系统（Operating System, OS）是指控制和管理整个计算机系统的硬件和软件资源，并合理地组织调度计算机的工作和资源的分配，以提供给用户和其他软件方便的接口和环境的程序集合。

> **★ 重点**：操作系统是计算机系统中最基本的系统软件，也是最接近硬件的一层软件。

- 计算机系统层次结构（自下而上）：裸机（纯硬件）→ 操作系统 → 应用程序 → 用户。操作系统处于硬件之上、应用软件之下。
- 裸机：不包含任何软件的纯硬件计算机（含 CPU、内存、硬盘、主板等）。在裸机上安装操作系统后，将其改造成功能更强、使用更方便的机器，这种覆盖了软件的机器称为扩充机器，又称虚拟机。

#### 💬 通俗理解
一句话：控制和管理整个计算机系统的硬件和软件资源，并合理地组织调度计算机的工作和资源的分配，以提供给用户和其他软件方便的接口和环境的程序集合。

### 模块：1.2 操作系统的四个特征

#### 1.2.1 并发 【熟练掌握】

#### 定义
- 并发：指两个或多个事件在同一时间间隔内发生。宏观上同时发生，微观上交替发生。
- 并行：指两个或多个事件在同一时刻同时发生。并发与并行的本质区别：并发是“同一时间间隔”、并行是“同一时刻”。

> **★ 重点**：单核 CPU 同一时刻只能执行一个程序，各程序只能并发执行；多核 CPU 同一时刻可同时执行多个程序，可并行执行。

- 操作系统伴随着“多道程序技术”出现，操作系统与程序并发是一起诞生的；并发性是操作系统最基本的特性。

#### 💬 通俗理解
像一个人同时炒两道菜：宏观上两盘都在做，微观上是切一会、炒一会地切换。

#### 📌 考察形式
选择题考概念对比与易混点辨析

#### 记忆技巧
单核 CPU 同一时刻只能执行一个程序，各程序只能并发执行；多核 CPU 同一时刻可同时执行多个程序，可并行执行。

#### 小结
像一个人同时炒两道菜：宏观上两盘都在做，微观上是切一会、炒一会地切换。

#### 1.2.2 共享 【熟练掌握】

#### 定义
- 共享即资源共享，指系统中的资源可供内存中多个并发执行的进程共同使用。分为互斥共享方式和同时共享方式。
- 互斥共享方式：一个时间段内只允许一个进程访问该资源。如摄像头同一时间段只能分配给 QQ 或微信其中一个进程。
- 同时共享方式：允许一个时间段内由多个进程“同时”访问。此“同时”往往是宏观上的，微观上可能交替访问（分时共享）。如 QQ 和微信同时读硬盘发送文件。

> **★ 重点**：并发与共享互为存在条件：失去并发性则共享无意义；失去共享性则无法实现并发。

#### 💬 通俗理解
多个进程要共用同一份资源；有的资源必须轮流独占（互斥），有的可以宏观上一起用。

#### 📌 考察形式
选择题考定义、特征与分类；偶有简答

#### 记忆技巧
并发与共享互为存在条件：失去并发性则共享无意义；失去共享性则无法实现并发。

#### 小结
多个进程要共用同一份资源；有的资源必须轮流独占（互斥），有的可以宏观上一起用。

#### 1.2.3 虚拟 【理解】

#### 定义
- 虚拟：指把一个物理上的实体变为若干个逻辑上的对应物。物理实体是实际存在的，逻辑对应物是用户感受到的。
- 时分复用技术（虚拟处理器技术）：单核 CPU 在微小时间段内交替为各进程服务，用户感觉有多个 CPU。
- 空分复用技术（虚拟存储器技术）：实际只有 4GB 内存，用户感觉内存远大于 4GB。

#### 💬 通俗理解
把一份真实硬件“变戏法”成多份逻辑资源，例如假的多 CPU、假的超大内存。

#### 📌 考察形式

#### 小结
把一份真实硬件“变戏法”成多份逻辑资源，例如假的多 CPU、假的超大内存。

#### 1.2.4 异步 【熟练掌握】

#### 定义
- 异步：多道程序环境下允许多个程序并发执行，但由于资源有限，进程的执行不是一贯到底，而是走走停停，以不可预知的速度向前推进。

> **★ 重点**：没有并发和共享，就谈不上虚拟和异步，因此并发和共享是操作系统两个最基本的特征。

| 特征 | 含义 | 关键点 |
| --- | --- | --- |
| 并发 | 多个事件同一时间间隔内发生 | 宏观同时、微观交替 |
| 共享 | 资源供多个并发进程共同使用 | 互斥共享 + 同时共享 |
| 虚拟 | 一个物理实体变为多个逻辑对应物 | 时分复用 + 空分复用 |
| 异步 | 进程走走停停、速度不可预知 | 因资源有限而争抢 |

#### 💬 通俗理解
进程不能一口气跑完，总是走走停停，前进速度不可预知。

#### 记忆技巧
没有并发和共享，就谈不上虚拟和异步，因此并发和共享是操作系统两个最基本的特征。

#### 小结

### 模块：1.3 操作系统的发展与分类

- 手工操作阶段：用户独占全机，人机速度矛盾导致资源利用率极低。
- 单道批处理系统：引入脱机输入/输出技术（外围机 + 磁带），由监督程序控制作业输入输出（操作系统的雏形）。优点：缓解一定人机速度矛盾；缺点：内存仅能有一道程序，CPU 大量时间空闲等待 I/O，资源利用率仍低。
- 多道批处理系统：每次往内存读入多道程序，操作系统正式诞生，支持多道程序并发运行。优点：资源利用率大幅提升、系统吞吐量增大；缺点：用户响应时间长、无人机交互功能（无法调试、无法中途输入参数）。
- 分时操作系统：以时间片为单位轮流为各用户/作业服务，各用户通过终端交互。优点：用户请求可即时响应、解决人机交互问题、多用户相互独立；缺点：不能优先处理紧急任务（完全公平、不区分紧急性）。
- 实时操作系统：接到外部信号后及时处理，并在严格时限内完成，主要特点是及时性和可靠性。分硬实时（导弹控制、自动驾驶）与软实时（12306 订票系统）。优点：能优先响应紧急任务，不需时间片排队。
- 网络操作系统：伴随计算机网络诞生，实现数据传送、资源共享与计算机间通信（如 Windows NT）。
- 分布式操作系统：主要特点是分布性和并行性，各计算机地位相同，并行协同完成任务。
- 个人计算机操作系统：如 Windows XP、MacOS，方便个人使用。
| 发展阶段 | 主要解决问题 | 主要优点 | 主要缺点 |
| --- | --- | --- | --- |
| 手工操作 | 无 | 无 | 独占全机、利用率极低 |
| 单道批处理 | 缓解人机矛盾 | 一定程度提升利用率 | CPU 等待 I/O、利用率仍低 |
| 多道批处理 | 提高资源利用率 | 并发执行、吞吐量大 | 响应时间长、无人机交互 |
| 分时系统 | 人机交互 | 即时响应、多用户 | 不能优先处理紧急任务 |
| 实时系统 | 及时可靠响应 | 优先处理紧急任务 | 实现复杂 |

### 模块：1.4 操作系统的运行机制

#### 1.4.1 指令：特权指令 vs 非特权指令 【理解】

#### 定义
- 指令是 CPU 能识别、执行的最基本命令（二进制机器指令）。一条高级语言代码翻译后可能对应多条机器指令。
- 特权指令：影响重大、只允许操作系统内核使用的指令，如内存清零指令。
- 非特权指令：应用程序只能使用的指令，如加法、减法指令。CPU 在设计生产时就划分了特权与非特权指令。

#### 💬 通俗理解
指令是 CPU 能识别、执行的最基本命令（二进制机器指令）。一条高级语言代码翻译后可能对应多条机器指令。

#### 1.4.2 内核态 vs 用户态 【熟练掌握】

#### 定义
> **★ 重点**：CPU 用程序状态字寄存器（PSW）中的某标志位区分状态：1 表示内核态（核心态/管态），0 表示用户态（目态）。

- 内核态：正在运行内核程序，可执行特权指令；用户态：正在运行应用程序，只能执行非特权指令。
- 内核程序：操作系统开发者（如微软、苹果）实现的程序，众多内核程序组成操作系统内核（Kernel），内核是最重要、最接近硬件的部分。

#### 💬 通俗理解
操作系统“开挂模式”：能执行特权指令、管硬件；应用程序平时在用户态。

#### 📌 考察形式
选择题考概念对比与易混点辨析

#### 记忆技巧

#### 小结
操作系统“开挂模式”：能执行特权指令、管硬件；应用程序平时在用户态。

#### 1.4.3 内核态与用户态的切换 【熟练掌握】

#### 定义
> **★ 重点**：内核态 → 用户态：执行一条特权指令修改 PSW 标志位为“用户态”，意味着操作系统主动让出 CPU 使用权。

> **★ 重点**：用户态 → 内核态：由“中断”引发，硬件自动完成变态过程，触发中断信号意味着操作系统强行夺回 CPU 使用权。

- 一个程序在用户态执行特权指令属于非法事件，会引发中断信号，CPU 检测到中断后立即变为核心态，转去运行处理中断的内核程序。

#### 💬 通俗理解
操作系统“开挂模式”：能执行特权指令、管硬件；应用程序平时在用户态。

#### 📌 考察形式
选择题考步骤顺序；简答题考完整过程描述

#### 记忆技巧
内核态 → 用户态：执行一条特权指令修改 PSW 标志位为“用户态”，意味着操作系统主动让出 CPU 使用权。；用户态 → 内核态：由“中断”引发，硬件自动完成变态过程，触发中断信号意味着操作系统强行夺回 CPU 使用权。

#### 小结
操作系统“开挂模式”：能执行特权指令、管硬件；应用程序平时在用户态。

### 模块：1.5 中断和异常

#### 1.5.1 中断的作用 【熟练掌握】

#### 定义
> **★ 重点**：“中断”是让操作系统内核夺回 CPU 使用权的唯一途径。没有中断机制，就不可能实现操作系统，也不可能实现程序并发。

- 中断会使 CPU 由用户态变为内核态，使操作系统重新夺回对 CPU 的控制权；凡是需要操作系统介入的地方，都会触发中断信号。

#### 💬 通俗理解
外面来的“叫停铃”，让 CPU 立刻把控制权还给操作系统。

#### 📌 考察形式

#### 小结
外面来的“叫停铃”，让 CPU 立刻把控制权还给操作系统。

#### 1.5.2 中断的分类 【理解】

#### 定义
| 分类 | 信号来源 | 与当前指令关系 | 例子 |
| --- | --- | --- | --- |
| 内中断（异常） | CPU 内部 | 与当前执行指令有关 | 非法指令、除 0、陷入 |
| 外中断（狭义中断） | CPU 外部 | 与当前执行指令无关 | 时钟中断、I/O 中断 |

- 内中断（异常）：来源于 CPU 内部、与当前执行的指令有关。如用户态执行特权指令、除数为 0、执行陷入指令。
- 外中断：来源于 CPU 外部、与当前执行的指令无关。如时钟中断（时钟部件每隔一个时间片发一次）、I/O 中断（输入输出任务完成时发送）。每一条指令执行结束时 CPU 都会例行检查是否有外中断信号。

#### 💬 通俗理解
外面来的“叫停铃”，让 CPU 立刻把控制权还给操作系统。

#### 📌 考察形式
选择题考定义、特征与分类；偶有简答

#### 小结
外面来的“叫停铃”，让 CPU 立刻把控制权还给操作系统。

#### 1.5.3 内中断（异常）的再分类 【熟练掌握】

#### 定义
| 异常类型 | 产生原因 | 内核处理方式 |
| --- | --- | --- |
| 陷入（trap/陷阱） | 由陷入指令故意引发（如系统调用） | 转去执行相应处理程序 |
| 故障（fault） | 错误条件引起，可被修复 | 修复后把 CPU 使用权还给应用程序继续执行 |
| 终止（abort） | 致命错误，无法修复 | 直接终止该应用程序，不归还 CPU |

- 故障例：缺页故障，内核修复后继续执行原程序。终止例：整数除 0、非法使用特权指令。

> **★ 重点**：大多数教材/试卷中，“中断”特指狭义的外中断，而内中断一般称为“异常”。

### 模块：1.8 操作系统引导（Boot）

- 引导（开机）过程：
1. ①CPU 从一个特定主存地址开始取指令，执行 ROM 中的引导程序（先进行硬件自检，再开机）。
1. ②将磁盘第一块——主引导记录（MBR）读入内存，执行磁盘引导程序，扫描分区表。
1. ③从活动分区（主分区，即安装操作系统的分区）读入分区引导记录（PBR），执行其中的程序。
1. ④从根目录下找到完整的操作系统初始化程序（即启动管理器）并执行，完成“开机”的一系列动作。
> **★ 重点**：引导顺序记忆：ROM 引导程序 → 主引导记录(MBR) → 分区引导记录(PBR) → 启动管理器/初始化程序。

### 模块：1.9 虚拟机

- 虚拟机：使用虚拟化技术，将一台物理机器虚拟化为多台虚拟机器（VM），每台虚拟机都可独立运行一个操作系统。
- 虚拟机管理程序（VMM，同义：虚拟机监控程序 / Virtual Machine Monitor / Hypervisor）分为两类：
| 类型 | 运行位置 | 典型软件 |
| --- | --- | --- |
| 第一类 VMM | 直接运行在硬件上（裸机） | 服务器虚拟化产品 |
| 第二类 VMM | 运行在宿主操作系统之上 | VirtualBox、VMware |
- 支持虚拟化的 CPU 通常划分更多指令等级（Ring 0 为最高权限、Ring 3 为最低权限），以隔离客户机与 VMM。

#### 2.1.1 进程的概念、组成与特征 【熟练掌握】

#### 定义
- 程序是静态的，是存放在磁盘里的可执行文件（如 QQ.exe）；进程是动态的，是程序的一次执行过程。同一个程序多次执行会对应多个进程。
- 进程实体（进程映像）由三部分组成：PCB（进程控制块）、程序段、数据段。其中 PCB 是给操作系统用的，程序段和数据段是给进程自己用的。

> **★ 重点**：PCB 是进程存在的唯一标志。进程被创建时操作系统为其创建 PCB，进程结束时回收其 PCB；操作系统对进程进行管理所需的一切信息都保存在 PCB 中。

- PCB 中保存的信息：进程描述信息（PID、UID）、资源分配信息（内存、I/O 设备、文件）、运行情况信息（CPU 使用时间、网络流量等），以及进程状态 state、优先级、程序计数器、寄存器等运行环境。

> **★ 重点**：进程的定义：进程是进程实体的运行过程，是系统进行资源分配和调度的一个独立单位。注意区分——进程是动态的，进程实体（进程映像）是静态的，进程实体反映了进程在某一时刻的状态。

- 进程的特征：①动态性（最基本特征）；②并发性；③独立性（进程是能独立运行、独立获取资源、独立接受调度的基本单位）；④异步性（会导致并发执行结果不确定，需要进程同步解决）；⑤结构性（进程实体 = PCB + 程序段 + 数据段）。
- 注意：多个进程共享同一程序时，其 PCB、数据段各不相同，但程序段内容相同（如同时挂三个 QQ 对应三个进程，程序段都是 QQ 程序）。

#### 2.1.2 进程的状态与转换 【熟练掌握】

#### 定义
- 进程的三种基本状态：运行态（占用 CPU）、就绪态（已具备运行条件，等待 CPU）、阻塞态（等待某事件发生，如 I/O、等待资源）。此外还有创建态和终止态，共五种状态。

![图：进程的五种状态及其转换](figures/ch2_state.png)

*图：进程的五种状态及其转换*

- 五状态转换：创建态→就绪态（创建完成）；就绪态→运行态（被调度）；运行态→就绪态（时间片到/被抢占）；运行态→阻塞态（主动请求等待事件）；阻塞态→就绪态（等待的事件发生）；运行态→终止态（进程结束/异常）。

> **★ 重点**：就绪态和阻塞态都不能直接到运行态：就绪态→运行态靠“调度”，运行态→就绪态靠“时间片到/被抢占”；阻塞态不能直接到运行态，必须先回到就绪态。运行态→阻塞态只能由进程“主动”发出（等待事件），阻塞态→就绪态只能由“被动”触发（事件发生）。

> **★ 重点**：单 CPU 系统中，同一时刻最多只有一个进程处于运行态；多核 CPU 下可有多个进程同时处于运行态。进程整个生命周期中大部分时间处于三种基本状态。

- 进程的组织方式：①链接方式——用执行指针、就绪队列指针、阻塞队列指针把 PCB 串成队列（可再按阻塞原因分成多个阻塞队列）；②索引方式——用就绪索引表、阻塞索引表记录 PCB 地址。
- 七状态模型（引入挂起态）：在五状态基础上增加“就绪挂起”和“阻塞挂起”。挂起态是把进程映像调到外存（内存不够时），阻塞态下进程映像仍在内存。挂起与阻塞都是暂时不能获得 CPU，但原因不同。
- PCB 中有一个变量 state 表示进程当前状态（如 1=创建态、2=就绪态、3=运行态、4=阻塞态、5=终止态）。

#### 2.1.3 进程控制（原语） 【熟练掌握】

#### 定义
- 进程控制就是要实现进程状态的转换，用“原语”实现。原语是一种特殊的程序段，其执行具有原子性（一气呵成、不可中断）。

> **★ 重点**：原语的原子性通过“关中断指令 + 开中断指令”这一对特权指令实现：关中断后 CPU 不再例行检查中断信号，直到开中断后才恢复，两者之间的指令序列就不可被中断。

- 相关原语：创建原语（创建态→就绪态）、撤销原语（就绪/阻塞/运行态→终止态→无）、阻塞原语（运行态→阻塞态）、唤醒原语（阻塞态→就绪态）、切换原语（运行态→就绪态、就绪态→运行态）。

> **★ 重点**：阻塞原语与唤醒原语必须成对使用：因何事阻塞，就由何事唤醒。进程自己请求终止用 exit 系统调用；整数除 0、非法使用特权指令会被 OS 强行杀掉。

- 无论哪个进程控制原语，要做的无非三类事情：①更新 PCB 中的信息（所有原语一定都会修改 state 标志；剥夺 CPU 必须保存运行环境，重新运行前必须恢复运行环境）；②将 PCB 插入合适的队列；③分配/回收资源。
- 进程上下文（Context）：进程运行过程中 CPU 各寄存器（PC、PSW、通用寄存器等）的现场信息。进程切换时，把原进程的运行环境保存到 PCB，再恢复新进程的运行环境，从而实现“还能切回来”。

正在运行的程序实例：有自己的身份、资源与运行现场。

#### 2.1.4 进程通信（IPC） 【熟练掌握】

#### 定义
- 进程是分配系统资源的单位，各进程地址空间相互独立，一个进程不能直接访问另一个进程的地址空间，因此需要操作系统支持来实现进程间通信。
- 共享存储：操作系统在内存中划出一块共享存储区，多个进程通过增加页表项/段表项把它映射到各自地址空间。访问时需互斥（用 PV 操作）。
- 共享存储分两种：基于数据结构的共享（如只能放一个长度为 10 的数组，速度慢、限制多、低级）；基于存储区的共享（数据形式和位置由进程控制，速度快、高级）。
- 消息传递：以格式化的消息（Message）为单位，通过“发送消息/接收消息”两个原语交换数据。消息由消息头（发送进程 ID、接收进程 ID、消息长度）和消息体组成。
- 消息传递分两种：直接通信方式（点名道姓，send(Q, msg) / receive(P, &msg)，发送时指明接收进程 ID）；间接通信方式（信箱通信，send(A, msg) / receive(A, &msg)，以信箱为中间实体，可多对多）。

> **★ 重点**：管道通信：管道是一个特殊的共享文件（pipe 文件），本质是内存中大小固定的缓冲区。特点：①只能半双工通信，双向需设两个管道；②各进程互斥访问；③写满时写进程阻塞，读空时读进程阻塞；④数据一旦读出就彻底消失，因此一个管道通常只允许一个读进程（或让各读进程轮流读）。

- 信号（Signal）：用于通知进程某个特定事件已发生，是一种进程通信机制（区别于实现同步互斥的“信号量”）。Linux 定义约 30 种信号，如 SIGINT（Ctrl+C 中断）、SIGFPE（浮点异常/除 0）、SIGKILL（杀死进程）、SIGWINCH（窗口大小变化）。
- 信号处理：进程从内核态返回用户态时例行检查 pending 中是否有待处理信号；重复收到的同类信号被丢弃（仅 1 bit 记录）；同时收到多个信号先处理序号小的。进程可自定义信号处理程序覆盖默认处理。

| 通信方式 | 实现机制 | 特点 | 典型场景 |
| --- | --- | --- | --- |
| 共享存储 | 划共享内存区映射到各进程 | 速度快（高级），需互斥 | 大量数据交换 |
| 消息传递 | send/receive 原语 + 消息 | 格式化消息，直接/间接(信箱) | 进程间定向通信 |
| 管道通信 | pipe 文件（固定缓冲区） | 半双工、读走即消失 | 父子进程流式通信 |
| 信号 | pending/blocked 位向量 | 通知事件发生，异步 | Ctrl+C、除0等事件 |

正在运行的程序实例：有自己的身份、资源与运行现场。

#### 2.1.5 线程的概念、实现方式与模型 【熟练掌握】

#### 定义
- 引入线程的目的：提高并发度。传统进程只能串行执行一系列程序；引入线程后，线程成为程序执行流的最小单位、CPU 执行单元（“轻量级进程”）。

> **★ 重点**：引入线程后：进程是除 CPU 之外系统资源的分配单元（内存、I/O 设备等分配给进程）；线程是处理机（CPU）的分配单元。进程内各线程共享进程的地址空间和资源。

- 线程的实现方式：①用户级线程（ULT）——由应用程序通过线程库实现，线程切换在用户态即可完成，OS 内核意识不到线程存在；优点开销小、效率高，缺点一个线程阻塞则整个进程阻塞、多线程无法在多核上并行。
- 线程的实现方式：②内核级线程（KLT）——由操作系统内核管理，OS 为每个内核级线程建立 TCB，切换必须在核心态完成；优点并发能力强、可在多核上并行，缺点线程管理开销大。

> **★ 重点**：操作系统只“看得见”内核级线程，因此只有内核级线程才是处理机分配的单位。用户级线程是“代码逻辑”的载体，内核级线程是“运行机会”的载体。

| 多线程模型 | 映射关系 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 一对一 | 1 个 ULT 映射 1 个 KLT | 一个线程阻塞不影响其他、可并行 | 占用内核级线程多、开销大 |
| 多对一 | 多个 ULT 映射 1 个 KLT | 切换在用户空间、开销小 | 一个阻塞全体阻塞、不可并行 |
| 多对多 | n 个 ULT 映射 m 个 KLT(n≥m) | 折中：并发度好、开销适中 | 实现较复杂 |

- 线程的状态与转换（2022 大纲新增）：线程同样有就绪、运行、阻塞等状态，切换时需保存/恢复运行环境，由 TCB 组织管理。

#### 💬 通俗理解
进程里更轻的执行流；同进程线程共享地址空间，切换更便宜。

#### 📌 考察形式
选择题考定义、特征与分类；偶有简答

#### 2.2.1 调度的概念与层次 【熟练掌握】

#### 定义
- 调度：当有一堆任务要处理而资源有限时，按某种规则决定处理顺序。

> **★ 重点**：三级调度：高级调度（作业调度）从外存后备队列选作业调入内存并创建进程，每个作业只调入调出一次；中级调度（内存调度）决定把哪个挂起进程调回内存，可多次调入调出；低级调度（进程调度）从就绪队列选进程分配 CPU，频率最高（一般几十毫秒一次）。

| 调度层次 | 要做什么 | 发生在 | 频率 | 对状态的影响 |
| --- | --- | --- | --- | --- |
| 高级调度 | 选作业调入内存并建进程 | 外存→内存（面向作业） | 最低 | 无→创建态→就绪态 |
| 中级调度 | 选挂起进程调回内存 | 外存→内存（面向进程） | 中等 | 挂起态→就绪态 |
| 低级调度 | 选进程分配处理机 | 内存→CPU | 最高 | 就绪态→运行态 |

> **★ 重点**：进程调度（低级调度）是操作系统中最基本的调度，任何操作系统都必须配置。

#### 2.2.2 调度的时机、切换与过程、方式 【熟练掌握】

#### 定义
- 需要进行调度的情况：①主动放弃——进程正常终止、运行中异常终止、主动请求阻塞（如等 I/O）；②被动放弃——时间片用完、有更紧急的事（如 I/O 中断）、有更高优先级进程进入就绪队列。

> **★ 重点**：不能进行调度与切换的三种情况：①在处理中断的过程中；②进程处于操作系统内核程序临界区中；③在原子操作（原语）过程中。注意：进程处于“普通临界区”时是可以调度切换的（如打印机等慢速设备临界区，若不切换会导致 CPU 空闲）。

- 调度方式：非剥夺（非抢占）方式——只允许进程主动放弃处理机，实现简单但无法及时处理紧急任务，适合早期批处理；剥夺（抢占）方式——有更紧迫进程时强行剥夺处理机，适合分时、实时系统。
- 狭义进程调度 = 从就绪队列选中一个要运行的进程；进程切换 = 一个进程让出处理机、另一个占用处理机的过程；广义进程调度 = 选中进程 + 进程切换。切换要保存/恢复原/新进程的现场信息。

> **★ 重点**：进程切换是有代价的，过于频繁调度切换会使系统大部分时间花在切换上，降低效率。

#### 2.2.3 调度算法的评价指标 【熟练掌握】

#### 定义
**CPU 利用率 = 忙碌时间 / 总时间**

**系统吞吐量 = 总共完成的作业数 / 总共花费的时间**

**（作业）周转时间 = 作业完成时间 − 作业提交时间**

**带权周转时间 = 周转时间 / 实际运行时间（必然 ≥ 1，越小越好）**

**等待时间 = 周转时间 − 运行时间（纯计算型进程；若含 I/O 再减去 I/O 时间）**

- 平均周转时间 = 各作业周转时间之和 / 作业数；平均带权周转时间、平均等待时间同理。
- 响应时间 = 从用户提交请求到首次产生响应所用的时间（交互式系统更关心）。

> **★ 重点**：调度算法其实只会影响作业/进程的等待时间（被 CPU/I/O 服务的总时长固定不变），因此评价调度算法主要看平均等待时间、平均周转时间、平均带权周转时间。

#### 2.2.4 调度算法 【熟练掌握】

#### 定义
- 先来先服务（FCFS）：按到达先后顺序服务，非抢占式，公平、实现简单；但对短作业不利，带权周转时间大，不会导致饥饿。
- 短作业优先（SJF，进程调度称 SPF）：选当前已到达且要求服务时间最短的作业/进程。默认非抢占式，追求最少平均等待/周转时间。

> **★ 重点**：SJF 的抢占式版本叫最短剩余时间优先（SRTN）：每当有进程到达就绪队列（或当前进程完成）就重新调度，若新进程剩余时间更短则抢占。注意：不加前提的“SJF 平均等待/周转最少”不严谨，正确说法是“所有进程同时到达（或同时可运行）时 SJF 平均等待/周转最少”，否则应说 SRTN 最少。

- SJF 优缺点：对短作业有利、对长作业不利，可能产生饥饿（源源不断的短作业使长作业饿死）；运行时间由用户提供不一定真实。

**响应比 = (等待时间 + 要求服务时间) / 要求服务时间 = 1 + 等待时间/要求服务时间（响应比 ≥ 1）**

- 高响应比优先（HRRN）：非抢占式，每次调度时计算各就绪进程的响应比，选响应比最高者。等待时间相同则短作业优先（SJF 优点），服务时间相同则等待长优先（FCFS 优点），兼顾了等待时间和运行时间，不会饥饿。
- 时间片轮转（RR）：按到达顺序轮流执行一个时间片，未执行完则剥夺处理机放回队尾。抢占式，由时钟中断通知时间片到。公平、响应快，适用于分时系统；但频繁切换有开销、不区分紧急程度。

> **★ 重点**：RR 时间片大小的影响：时间片太大则退化为 FCFS 且增大响应时间；时间片太小则切换过于频繁、真正执行时间比例减少。一般设计使切换开销占比不超过 1%。

- 优先级调度：调度时选优先级最高者。分静态/动态优先级；抢占式、非抢占式都有。通常系统进程 > 用户进程，前台 > 后台，I/O 型进程 > 计算型进程（让 I/O 设备尽早投入工作，提升资源利用率）。若源源不断有高优先级进程到来，可能导致饥饿。
- 多级反馈队列：设置多级就绪队列，优先级从高到低、时间片从小到大；新进程先入第 1 级队列按 FCFS 排队，时间片用完未结束则进入下一级队尾；只有第 k 级队列为空才调度 k+1 级队头进程；抢占式（更高级队列来新进程会抢占）。

> **★ 重点**：多级反馈队列综合了多种算法优点：对各类型进程相对公平（FCFS）、新进程响应快（RR）、短进程较快完成（SPF）、无需事先估计运行时间，但可能导致饥饿。UNIX 就采用多级反馈队列调度。

| 算法 | 是否抢占 | 考虑因素 | 优缺点 | 会饥饿 |
| --- | --- | --- | --- | --- |
| FCFS | 非抢占 | 等待时间 | 公平简单；对短作业不利 | 不会 |
| SJF/SPF | 默认非抢占(SRTN抢占) | 运行时间 | 平均等待/周转少；对长作业不利 | 会 |
| HRRN | 非抢占 | 等待+运行时间 | 折中均衡；计算响应比 | 不会 |
| RR | 抢占 | 时间片轮转 | 公平响应快；频繁切换有开销 | 不会 |
| 优先级 | 两者都有 | 优先级 | 区分紧急程度；可能饿死低优先级 | 会 |
| 多级反馈队列 | 抢占 | 多队列+时间片 | 综合平衡优秀；较复杂 | 会 |

#### 2.3.1 同步与互斥的基本概念 【熟练掌握】

#### 定义
- 进程同步：进程具有异步性（各进程以独立、不可预知速度推进），需要同步机制保证并发进程按要求有序推进（直接制约关系）。
- 临界资源：一个时间段内只允许一个进程使用的资源（如打印机、摄像头、某些变量/缓冲区）。对临界资源的访问必须互斥。
- 临界区：访问临界资源的那段代码。对临界资源的互斥访问逻辑上分四部分：进入区（检查+上锁）、临界区、退出区（解锁）、剩余区。

> **★ 重点**：实现互斥应遵循四原则：①空闲让进；②忙则等待；③有限等待（保证不会饥饿）；④让权等待（不能进入临界区时立即释放处理机，防止忙等待）。

#### 2.3.2 进程互斥的软件实现方法 【熟练掌握】

#### 定义
- 单标志法：设置 turn，轮到谁谁进。能实现互斥，但必须轮流进入，若持权进程一直不访问临界区，则另一进程无法进入，违背“空闲让进”。
- 双标志先检查法：先检查对方意愿再上锁。若按“检查—切换—检查—切换—上锁—上锁”执行，两进程会同时进入临界区，违背“忙则等待”。原因：检查与上锁无法一气呵成。
- 双标志后检查法：先上锁再检查。解决了“忙则等待”，但两进程可能都上锁后互相等待，违背“空闲让进”和“有限等待”，会饥饿。

> **★ 重点**：Peterson 算法：结合双标志法（表达意愿 flag[]）与单标志法（表达谦让 turn）。谁最后说了“客气话”（把 turn 让给对方），谁就失去优先权。遵循了空闲让进、忙则等待、有限等待三原则，但依然未遵循“让权等待”，会忙等。

| --- | --- | --- |
| 单标志法 | turn | 空闲让进 |
| 双标志先检查 | flag[] | 忙则等待 |
| 双标志后检查 | flag[] | 空闲让进、有限等待 |
| Peterson | flag[] + turn | 让权等待（其余三原则满足） |

#### 2.3.4 信号量机制（PV 操作） 【熟练掌握】

#### 定义
- 信号量就是一个变量，表示系统中某种资源的数量。用户进程通过一对原语 wait(S)/signal(S)（即 P(S)/V(S)）操作信号量。P、V 来自荷兰语 proberen 和 verhogen。
- 整型信号量：用一个整数变量表示资源数，P 检查与减一原子完成；缺点不满足让权等待，会忙等。

> **★ 重点**：记录型信号量：S.value 初值表示资源数目；P(S) 执行 S.value--，若 value<0 则 block 自我阻塞（运行态→阻塞态），插入 S.L 等待队列；V(S) 执行 S.value++，若 value≤0 则 wakeup 唤醒等待队列中第一个进程（阻塞态→就绪态）。遵循让权等待，不忙等。

> **★ 重点**：信号量的值 = 该资源的剩余数量；若值为负，其绝对值表示等待该资源的进程数。对信号量的操作只有三种：初始化、P、V。考研题目中 P(S)、V(S) 默认 S 为记录型信号量。

- 用信号量实现进程互斥：设互斥信号量 mutex 初值为 1；进入区 P(mutex)，退出区 V(mutex)。对不同临界资源设不同互斥信号量；P、V 必须成对出现。

> **★ 重点**：用信号量实现进程同步（一前一后）：设同步信号量初值为 0；在“前操作”之后执行 V(S)，在“后操作”之前执行 P(S)——口诀“前 V 后 P”。前驱关系本质上就是多级同步问题，每一对前驱关系设一个同步信号量。

- PV 解题三步：①关系分析（找同步、互斥关系）；②整理思路（定 P、V 大致顺序）；③设置信号量并确定初值（互斥初值 1，同步初值看对应资源初始数量）。

#### 2.3.5 经典同步问题 【熟练掌握】

#### 定义
- 生产者-消费者问题：一组生产者、一组消费者共享初始为空、大小为 n 的缓冲区。设 mutex=1（互斥）、empty=n（空闲缓冲区数）、full=0（产品数）。生产者：P(empty)→P(mutex)→放入→V(mutex)→V(full)；消费者：P(full)→P(mutex)→取出→V(mutex)→V(empty)。

![图：生产者-消费者问题模型](figures/ch2_producer.png)

*图：生产者-消费者问题模型*

> **★ 重点**：生产者-消费者死锁陷阱：实现互斥的 P(mutex) 必须放在实现同步的 P(empty)/P(full) 之后。若 P(mutex) 在前，缓冲区满时生产者先锁住临界区再因 empty=0 阻塞，消费者又因 mutex=0 阻塞，两者循环等待，发生死锁。两个 V 操作顺序可交换（V 不会阻塞）。

- 多生产者-多消费者问题（父母放水果、儿女吃水果）：关键是理清“事件”的前后关系。把“四对进程行为前后关系”抽象为“盘子变空事件→放水果事件”一对关系，用一个 plate 信号量即可。

> **★ 重点**：缓冲区大小为 1 时，同步信号量可能同时天然保证互斥（任一时刻最多一个进程的 P 不被阻塞），可不设 mutex；但缓冲区大小大于 1 时必须专门设 mutex 保证互斥访问，否则两生产者可能同时写缓冲区导致数据覆盖。考试拿不准时加上 mutex，且互斥 P 放同步 P 之后。

- 读者-写者问题：允许多个读者同时读，但写者与任何其他进程互斥。核心：设 rw=1（共享文件互斥）、count 记录读者数、mutex=1（保护 count）。第一个读者 P(rw) 加锁，最后一个读者 V(rw) 解锁。

> **★ 重点**：读者-写者问题中，count 变量的检查和赋值必须用 mutex 保护（否则两读者都满足 count==0 会重复 P(rw) 导致阻塞）。普通“读优先”算法中写者可能饿死；增设 w 信号量（读写公平法）可实现“写者不会饥饿”。

- 哲学家进餐问题：5 个哲学家、5 根筷子，每人需同时拿左右两根筷子才能吃饭，只拿一根会死锁。设 chopstick[5] 初值全 1。

*图：哲学家进餐问题*

> **★ 重点**：哲学家进餐防死锁三种思路：①最多允许 4 个哲学家同时进餐（保证至少一人能拿齐筷子）；②奇数号先拿左、偶数号先拿右（破坏循环等待）；③仅当左右筷子都可用时才允许拿起（用 mutex 把“取两根筷子”变成原子操作，或信号量实现）。

### 模块：2.4 死锁

#### 2.4.1 死锁的概念 【熟练掌握】

#### 定义
- 死锁：并发环境下，各进程因竞争资源而互相等待对方手里的资源，导致各进程都阻塞、都无法向前推进的现象。若无外力干涉，这些进程都无法推进。

> **★ 重点**：死锁、饥饿、死循环的区别：死锁一定是循环等待资源导致，至少两个进程同时发生，死锁进程一定处于阻塞态；饥饿可能只有一个进程，可能是阻塞态或就绪态；死循环可能只有一个进程，可处于运行态，由代码逻辑错误导致。死锁和饥饿是管理者（OS）的问题，死循环是被管理者（程序）的问题。

| 现象 | 是否循环等待 | 进程数 | 进程状态 | 原因 |
| --- | --- | --- | --- | --- |
| 死锁 | 一定循环等待资源 | 至少两个 | 阻塞态 | 资源分配策略不合理 |
| 饥饿 | 不一定 | 可能一个 | 阻塞态或就绪态 | 资源分配策略不合理 |
| 死循环 | 否 | 可能一个 | 可以是运行态 | 代码逻辑错误 |

> **★ 重点**：死锁产生的四个必要条件（缺一不可）：①互斥条件；②不剥夺条件（未用完不能被强夺）；③请求和保持条件（已持有资源又请求新资源，得不到也不释放已有）；④循环等待条件（存在循环等待链）。

> **★ 重点**：发生死锁时一定有循环等待，但发生循环等待时未必死锁（循环等待是死锁的必要不充分条件）。若每类资源只有一个，则循环等待就是死锁的充分必要条件；若同类资源数大于 1，即使有循环等待也未必死锁。

- 发生死锁的时机：①对不可剥夺资源的竞争（对可剥夺的 CPU 竞争不会死锁）；②进程推进顺序非法；③信号量使用不当（如互斥 P 放在同步 P 之前）。总之，对不可剥夺资源的不合理分配可能导致死锁。
- 死锁处理策略：①预防（破坏四条件之一）；②避免（防止进入不安全状态，银行家算法）；③检测和解除（允许死锁发生，检测后再解除）。

#### 2.4.2 预防死锁（破坏必要条件） 【熟练掌握】

#### 2.4.3 避免死锁（银行家算法） 【熟练掌握】

#### 定义
- 安全序列：系统按该序列分配资源，则每个进程都能顺利完成。只要找到一个安全序列，系统就处于安全状态（安全序列可能有多个）。

> **★ 重点**：安全状态一定不会死锁；不安全状态可能死锁（不一定死锁）；死锁时一定处于不安全状态。银行家算法核心思想：进程提出资源申请时先预判此次分配是否会导致系统进入不安全状态，若是则暂时不答应，让进程阻塞等待。

**Need[i, j] = Max[i, j] − Allocation[i, j]（各进程最多还需要多少资源）**

- 银行家算法数据结构：Available（长度 m 的数组，当前可用资源）、Max（n×m 矩阵，最大需求）、Allocation（n×m 矩阵，已分配）、Need = Max − Allocation（最多还需要）、Request（本次申请）。

> **★ 重点**：银行家算法四步：①若 Request ≤ Need 则转②，否则出错（超过声明的最大需求）；②若 Request ≤ Available 则转③，否则无足够资源、进程等待；③试探分配，更新 Available、Allocation、Need；④执行安全性算法，若安全才正式分配，否则恢复数据、让进程阻塞。

> **★ 重点**：安全性算法：检查当前 Available 能否满足某进程的 Need，能则把该进程加入安全序列并回收其全部资源（Available 增加），反复进行直到所有进程都加入（安全）或无法再加入（不安全）。手算时先找 Need 最小的可满足进程，加快求解。

#### 3.1.1 什么是内存 【熟练掌握】

#### 定义
- 内存（主存）可存放数据，程序执行前必须先放入内存中才能被 CPU 处理，其作用是缓和 CPU 与硬盘之间的速度矛盾。

#### 3.1.3 装入的三种方式 【熟练掌握】

### 模块：3.3 进程的内存映像

- 32 位系统中进程虚拟地址空间为 4GB，自上而下通常划分为：操作系统内核区（高地址 1GB，含内核代码、内核数据结构）、用户区（低地址 3GB）。

### 模块：3.6 动态分区分配算法

- 当多个空闲分区都能满足需求时，按算法从空闲分区表/链中选一个分配。四种算法：首次适应、最佳适应、最坏适应、邻近适应。
| 算法 | 分区排列顺序 | 分配规则 | 优点 | 缺点 |
| --- | --- | --- | --- | --- |
| 首次适应 | 地址递增 | 从低地址找第一个满足的 | 综合性能最好，开销小，回收后一般不用重排 | 低地址易积累小分区 |
| 最佳适应 | 容量递增 | 优先用最小能满足的分区 | 保留更多大分区，满足大进程 | 产生很多难以利用的小碎片，开销大 |
| 最坏适应 | 容量递减 | 优先用最大连续空闲区 | 减少小碎片 | 大分区迅速用完，不利于大进程 |
| 邻近适应 | 地址递增(循环链表) | 从上次查找结束位置开始找 | 不用每次从头查低地址小分区 | 高地址大分区被用完 |
> **★ 重点**：最佳适应会产生最多外部碎片；最坏适应（最大适应）会很快耗尽大分区；综合来看首次适应效果最好。
- 首次适应每次从头查，低地址小分区更可能被用、高地址大分区更可能保留；邻近适应使高低地址分区被用概率趋同，导致高地址大分区被划小、最终无大分区可用。

#### 3.7.2 页表 【熟练掌握】

#### 定义
- 为知道进程每个页面在内存中的位置，为每个进程建立一张页表（页表通常存于 PCB）。一个进程一张页表，每个页面对应一个页表项，每个页表项由页号和块号组成。

> **★ 重点**：页表记录的只是内存块号，而不是内存块的起始地址！J 号内存块的起始地址 = J × 内存块大小。

#### 3.7.3 逻辑地址结构 【熟练掌握】

#### 3.7.5 具有快表的地址变换机构 【熟练掌握】

#### 定义
- 快表（TLB，联想寄存器）：访问速度远快于内存的高速缓存，存放最近访问的页表项副本；内存中的页表称慢表。TLB 不是内存，一般集成在 CPU 内部。

> **★ 重点**：快表命中只需一次访存；快表未命中需两次访存（查慢表 + 访问内存），且应把找到的页表项同时存入快表，快表满则按算法替换旧表项。

**快表平均访问耗时 = 命中率 × (查快表时间 + 访存时间) + (1-命中率) × (查快表时间 + 查慢表时间 + 访存时间)**

- 例：查快表 1us、访存 100us、命中率 90%，则平均耗时 = (1+100)×0.9 + (1+100+100)×0.1 = 111us；若快慢表同时查找，则 = (1+100)×0.9 + (100+100)×0.1 = 110.9us。未采用快表时需 100+100 = 200us。

> **★ 重点**：局部性原理：时间局部性（循环导致某指令/数据近期被重复访问）+ 空间局部性（连续存放导致附近单元被访问）。这是快表与虚拟内存成立的理论基础。

#### 💬 通俗理解
页表的高速缓存（TLB），命中就少访问一次内存。

#### 📌 考察形式
选择题考公式与结果；综合题要求完整分步计算

#### 记忆技巧
快表命中只需一次访存；快表未命中需两次访存（查慢表 + 访问内存），且应把找到的页表项同时存入快表，快表满则按算法替换旧表项。；局部性原理：时间局部性（循环导致某指令/数据近期被重复访问）+ 空间局部性（连续存放导致附近单元被访问）。这是快表与虚拟内存成立的理论基础。

#### 3.7.6 两级页表 【熟练掌握】

#### 3.10.3 虚拟内存的定义与特征 【熟练掌握】

#### 定义
- 基于局部性原理，程序装入时只装入很快会用到的部分，暂时用不到的部分留在外存；执行中访问的信息不在内存时由 OS 调入，内存不够时把暂时不用的换出。用户看来似乎有比实际内存大得多的内存，即虚拟内存。

> **★ 重点**：虚拟内存三大特征：多次性（分多次调入）、对换性（运行中可换入换出）、虚拟性（逻辑上扩充内存容量）。

**虚拟内存最大容量 = 由计算机地址结构（CPU 寻址范围）决定；实际容量 = min(内存容量 + 外存容量, CPU 寻址范围)**

> **★ 重点**：虚拟内存实现必须建立在离散分配（请求分页/请求分段/请求段页式）基础上，连续分配不便实现；需提供请求调页（调段）和页面（段）置换两大功能。

#### 3.11.2 缺页中断机构 【熟练掌握】

#### 定义
- 访问的页面不在内存时产生缺页中断，由缺页中断处理程序处理；此时缺页进程阻塞、放入阻塞队列，调页完成后唤醒并放回就绪队列。
- 有内存空闲块时：分配空闲块、装入所缺页面、修改页表；无空闲块时：用页面置换算法选一页淘汰，若被修改过则写回外存，未修改过则不写回。

> **★ 重点**：缺页中断属于内中断（异常/故障）。一条指令执行期间可能产生多次缺页中断（如 copy A to B，A、B 属不同页面可产生两次）。

> **★ 重点**：缺页中断与普通中断的区别：①在指令执行期间产生（不是执行完才检测）；②一条指令可产生多次缺页；③处理后要恢复执行原指令（不是下一条）。

#### 💬 通俗理解

| FIFO | 淘汰最先进入内存的页面 | 实现简单；性能差，可能出现 Belady 异常 |
| LRU | 淘汰最近最久未使用的页面 | 性能好、接近 OPT；需硬件支持、开销大 |
| CLOCK/NRU | 循环扫描，淘汰访问位=0 的页面 | 实现简单、开销小；未考虑修改位 |
| 改进型CLOCK | 按 (0,0)→(0,1)→(1,0)→(1,1) 淘汰 | 开销较小、性能不错 |

#### 💬 通俗理解
内存满了还要进新页时，挑一页踢出去；OPT/FIFO/LRU/CLOCK 是不同踢人策略。

### 模块：3.14 内存映射文件

- 内存映射文件（Memory-Mapped Files）：操作系统向上层提供的系统调用功能，方便程序员访问文件数据、方便多个进程共享同一个文件。
- 传统文件访问：open（打开）→ seek（移动读写指针）→ read（从磁盘读入内存）→ write（写回磁盘），需多次系统调用。
- 内存映射方式：open 打开 → mmap 将文件映射到进程虚拟地址空间，之后以访问内存的方式访问文件数据，文件数据的读入/写出由 OS 自动完成，进程关闭文件时 OS 自动把被修改的数据写回磁盘。
> **★ 重点**：多个进程可映射同一文件实现共享：物理内存中文件对应同一份数据，一个进程修改后另一个进程可立即“看到”（通过各自页表映射到同一物理页）。

#### 4.2.4 索引顺序文件 【理解】

#### 定义
- 索引顺序文件 = 索引文件 + 顺序文件的结合：一组记录对应一个索引项（分组），组内为顺序文件。

**N 个记录分 √N 组，每组 √N 个，检索一个记录平均查找次数 = √N/2 + √N/2 = √N（约）**

- 例：10000 个记录，分 100 组，每组 100 个，平均查找 50+50 = 100 次；多级索引顺序文件可进一步降低查找次数。

**为 N 个记录建立 K 级索引，最优分组为每组 N^(1/(K+1)) 个记录，平均查找次数 = (N^(1/(K+1))/2) × (K+1)**

- 例：10^6 个记录建 2 级索引，最优每组 10^(6/3)=100 个，平均查找 (100/2)×3 = 150 次。

#### 4.4.4 链接分配（显式链接 / FAT） 【熟练掌握】

#### 4.4.5 索引分配 【熟练掌握】

#### 定义
- 为每个文件建立一张索引表，记录各逻辑块对应的物理块（类似页表）；索引表所在盘块称索引块，文件数据所在盘块称数据块。目录项记录索引块号。

> **★ 重点**：索引表是一个文件一张；FAT 是一个磁盘一张。索引分配支持随机访问、便于拓展，但索引表占空间，访问数据前要先读入索引块。

- 单个索引块容量有限（如块 1KB、索引项 4B 时一块只能存 256 项），文件超过该块数时用三种方案解决：链接方案、多层索引、混合索引。
- ① 链接方案：多个索引块用指针链接；访问最后一个索引块需顺序读入前面所有索引块，I/O 次数多、效率低。
- ② 多层索引：类似多级页表，第一层索引块指向第二层索引块，可继续建第三、四层。

**采用 K 层索引且顶级索引表未调入内存时，访问一个数据块需 K+1 次读盘；K 层索引的最大文件长度 = 256^K × 块大小（块 1KB、索引项 4B）**

- 例：两层索引最大长度 = 256×256×1KB = 64MB；三层索引 = 256^3×1KB = 16GB。各级索引表大小不能超过一个磁盘块。
- ③ 混合索引：顶级索引表中同时含直接地址、一级间接索引、二级间接索引，小文件访问更快。

### 模块：4.5 逻辑结构 VS 物理结构

- 逻辑结构从用户视角看文件内部数据如何组织（顺序/索引/索引顺序）；物理结构从 OS 视角看数据如何存放于外存（连续/链接/索引分配）。
> **★ 重点**：两个“随机访问”含义不同：逻辑结构支持随机访问 = 能根据记录号直接算出该记录的逻辑地址（定长记录顺序文件）；物理结构支持随机访问 = 能直接由逻辑块号得到物理块号（连续、显式链接 FAT、索引分配）。
- 顺序文件内部记录可顺序存储或链式存储；文件整体用连续/链接/索引分配由 OS 决定，二者独立。记录链式存储是用户自己设计，文件链接分配是 OS 决定。
- 索引文件的索引表由用户建立，映射“关键字 → 记录逻辑地址”；索引分配的索引表由 OS 建立，映射“逻辑块号 → 物理块号”。
| 物理结构 | 目录项关键内容 | 随机访问 | 文件拓展 | 碎片/空间 |
| --- | --- | --- | --- | --- |
| 连续分配 | 起始块号 + 长度 | 支持（且顺序最快） | 不便 | 有碎片、利用率低 |
| 隐式链接 | 起始块号 + 结束块号 | 不支持（i 块需 i+1 次 I/O） | 方便 | 无碎片、利用率高 |
| 显式链接 FAT | 起始块号 | 支持（查内存 FAT） | 方便 | 无碎片、占 FAT 空间 |
| 索引分配 | 索引块号 | 支持（先读索引块） | 方便 | 无碎片、索引表占空间 |

### 模块：4.7 文件的基本操作

- 创建文件（create）：在外存找空闲空间，并在目标目录创建目录项（文件名 + 存放位置等）。
- 删除文件（delete）：按路径找目录项，回收文件占用盘块（依空闲表/链表/位示图策略处理），删除目录项。
- 打开文件（open）：按路径找目录项并检查权限，把目录项复制到内存“打开文件表”，返回编号（文件描述符）；之后用文件描述符操作文件，无需再查目录。
- 关闭文件（close）：删除进程打开文件表对应表项，回收内存资源，系统打开文件表计数器减 1，减到 0 才删表项。
- 读文件（read）/写文件（write）：用文件描述符指明文件，从读/写指针处读入/写出指定大小数据。
> **★ 重点**：打开文件并不把文件数据读入内存；系统打开文件表全局一张，记录“打开计数器”；Windows 提示“文件正在使用无法删除”就是检查了该计数器。

### 模块：4.10 文件系统层次结构

- 自上而下（用户接口到设备）：用户接口 → 文件目录系统 → 存取控制模块 → 逻辑文件系统与文件信息缓冲区 → 物理文件系统 → 辅助分配模块 → 设备管理模块 → 设备。
- 各层职责：用户接口处理 read/write/open/close 系统调用；文件目录系统按路径找 FCB/索引结点、管理目录与打开文件表；存取控制模块验证权限；逻辑文件系统把记录号转成逻辑地址；物理文件系统把逻辑地址转成物理地址；辅助分配模块负责空间分配回收；设备管理模块负责设备分配、缓冲区、磁盘调度、启动/释放设备。
> **★ 重点**：记忆方法（删除文件最后 100 条记录的例子）：用户接口 → 文件目录系统（找目录项）→ 存取控制（验权限）→ 逻辑文件系统（记录号转逻辑地址）→ 物理文件系统（逻辑转物理地址）→ 设备管理（发磁盘请求）→ 辅助分配（回收盘块）。

### 模块：4.11 文件系统布局

- 磁盘从原始到可用依次：物理格式化（低级格式化，划分扇区、检测并替换坏扇区）→ 磁盘分区（分卷）→ 逻辑格式化（初始化文件系统）。
- 外存结构：主引导记录 MBR（含分区表）→ 引导块（启动时装入并运行）→ 超级块（文件系统关键信息）→ 空闲空间管理信息 → 索引结点 → 根目录 → 其余文件和目录。
- 内存结构：内存中维护分区表、目录缓存（近期访问的目录）、系统打开文件表、进程打开文件表等，用于加快检索与读写。

### 模块：4.12 虚拟文件系统与文件系统挂载

- 虚拟文件系统（VFS）向上层提供统一标准的系统调用接口，屏蔽底层不同文件系统的实现差异；要求下层文件系统必须实现规定的函数（open/read/write 等）。
> **★ 重点**：vnode 只存在于主存中；inode（索引结点）既会被调入主存也会存于外存。每打开一个文件，VFS 在主存新建一个 vnode，用统一结构表示文件，功能指针指向具体文件系统的实现。
- 文件系统挂载（mounting）：①在 VFS 中注册新文件系统（内存挂载表记录类型、容量等）；②向 VFS 提供函数地址列表；③把新文件系统挂到挂载点（某父目录下）。

#### 5.1.2 I/O 控制器 【熟练掌握】

#### 5.1.3 I/O 控制方式 【熟练掌握】

#### 定义
关注五个维度：①完成一次读写的流程；②CPU 干预频率；③数据传送单位；④数据流向；⑤主要优缺点。发展主线是“尽量减少 CPU 对 I/O 的干预”。

- 程序直接控制方式（关键词：轮询）：CPU 发出读指令后不断轮询状态寄存器，设备就绪后将数据寄存器内容读入 CPU 寄存器，再写入内存。每个字都需 CPU 帮助，CPU 长期忙等，利用率极低。
- 中断驱动方式（关键词：中断）：CPU 发出命令后即可切换其他进程，I/O 完成后控制器发出中断信号，CPU 在中断处理程序中读入一个字并写入主存。CPU 与设备可并行，但每个字仍经过 CPU，中断太频繁开销大。
- DMA 方式（Direct Memory Access，直接存储器存取）：以“块”为单位，数据直接从设备到内存（不经 CPU），仅在传送一个或多个连续块的开始和结束才需 CPU 干预，整块完成后才发中断。
- 通道控制方式（关键词：通道程序）：通道是“弱鸡版 CPU”，可识别并执行通道指令（通道程序放在主存，与 CPU 共享内存）。CPU 只发一次 I/O 指令指明通道程序位置和操作设备，之后通道自主完成一组数据块读写，完成后才发中断。

> **★ 重点**：DMA 控制器四个寄存器（必背）：DR 数据寄存器（暂存数据）、MAR 内存地址寄存器（输入时存目标内存地址/输出时存源地址）、DC 数据计数器（剩余字节数）、CR 命令/状态寄存器。

- DMA 限制：CPU 每发一条 I/O 指令只能读写一个或多个“连续”的数据块，且这些块在内存中也要连续；离散块需多次发指令、多次中断。

| 对比项 | 程序直接控制 | 中断驱动 | DMA | 通道控制 |
| --- | --- | --- | --- | --- |
| 完成方式 | CPU 不断轮询状态 | 设备完成发中断 | DMA 控制器传块后发中断 | 通道执行通道程序后发中断 |
| CPU 干预频率 | 极高 | 高 | 中 | 低 |
| 数据传送单位 | 字 | 字 | 块 | 一组块 |
| 数据流向 | 设备→CPU→内存 | 设备→CPU→内存 | 设备→内存（不经 CPU） | 设备→内存（通道控制） |
| 优点 | 实现简单 | CPU 与设备可并行 | 效率高、并行性好 | 资源利用率最高 |
| 主要缺点 | CPU 忙等、利用率低 | 中断频繁开销大 | 只能传连续块 | 实现复杂需专门硬件 |

#### 5.1.4 I/O 软件层次结构 【熟练掌握】

#### 定义
> **★ 重点**：I/O 软件四层（自上而下，必背顺序）：用户层软件 → 设备独立性软件 → 设备驱动程序 → 中断处理程序 → 硬件。越往上越接近用户，越往下越接近硬件，每层利用下层服务屏蔽细节向上层提供服务。

- 用户层软件：实现与用户交互的接口，提供库函数（如 printf），把用户请求翻译成格式化的 I/O 请求，通过系统调用请求内核服务。
- 设备独立性软件（又称设备无关性软件）：与硬件特性无关的功能几乎都在此层，六大功能见下条。

> **★ 重点**：设备独立性软件六大功能（必背）：①向上层提供统一调用接口（read/write）；②设备保护；③差错处理；④设备的分配与回收；⑤数据缓冲区管理；⑥建立逻辑设备名到物理设备名的映射（逻辑设备表 LUT），并按设备类型选择驱动程序。

- 逻辑设备表 LUT：记录“逻辑设备名 → 物理设备名 → 驱动程序入口地址”的映射。整系统一张 LUT（逻辑设备名不重复，适合单用户）；每个用户一张 LUT（逻辑设备名可重复，存于用户 PCB，适合多用户）。
- 设备驱动程序：把上层命令（read/write）转换成特定设备“听得懂”的操作，设置设备寄存器、检查设备状态。不同设备硬件特性不同（寄存器个数、状态位含义都不同），只有厂家知道，故厂家须提供对应驱动程序。
- 中断处理程序：I/O 完成后控制器发中断信号，系统按中断类型找到对应中断处理程序。流程：读设备状态 → 若正常则从设备读一个字经 CPU 放入内存缓冲区；若异常则做相应处理。

> **★ 重点**：层次归属判断技巧（高频考点）：直接涉及硬件具体细节、且与中断无关的操作 → 设备驱动程序层；不涉及硬件、对各类设备通用管理 → 设备独立性软件层；把用户请求翻译成系统调用 → 用户层软件。

#### 5.2.3 设备的分配与回收 【熟练掌握】

#### 定义
- 设备固有属性三类：独占设备（一个时段只分给一个进程）、共享设备（可同时分给多进程，宏观共享微观交替）、虚拟设备（用 SPOOLing 把独占设备改造成虚拟共享设备）。
- 设备分配算法：先来先服务、优先级高者优先、短任务优先等。

> **★ 重点**：安全分配方式 vs 不安全分配方式（必背）：安全分配——分配设备后即阻塞进程，I/O 完成才唤醒，破坏“请求和保持”条件不会死锁，但 CPU 与设备串行；不安全分配——分配后进程可继续执行并发新请求，CPU 与 I/O 可并行推进快，但可能死锁。

- 静态分配：进程运行前一次性分配全部资源，运行结束归还，破坏“请求和保持”不产生死锁；动态分配：运行过程中动态申请。
- 数据结构关系：一个通道控制多个控制器，一个控制器控制多个设备。

| 数据结构 | 作用 | 关键字段 |
| --- | --- | --- |
| 设备控制表 DCT | 每个设备一张，记录设备情况 | 设备类型、设备标识符、设备状态、指向控制器表指针、设备队列队首指针 |

#### 5.2.4 缓冲区管理 【熟练掌握】

#### 定义
- 缓冲区是存储区域，可用硬件寄存器（成本高、容量小，如联想寄存器）或内存实现。本节讨论“内存作为缓冲区”。
- 缓冲区作用：①缓和 CPU 与 I/O 设备之间速度不匹配的矛盾；②减少对 CPU 的中断频率（字符设备每输出一个字符发一次中断）；③解决数据粒度不匹配（进程一次生成一块、设备一次输出一个字符）；④提高 CPU 与 I/O 之间的并行性。
- 单缓冲：主存分配一个缓冲区（默认为一个块大小）。缓冲区非空时不能冲入只能传出；为空时可冲入但必须充满才能传出。

> **★ 重点**：单缓冲处理一块数据平均耗时（必背公式）：Max(C, T) + M。其中 T 为设备输入一块数据的时间，M 为缓冲区数据传送到工作区的时间，C 为 CPU 处理一块数据的时间。

- 双缓冲：分配两个缓冲区。处理一块数据平均耗时为 Max(T, C+M)。

![图 5-3  双缓冲策略（设备与 CPU 交替使用两个缓冲区）](figures/ch5_doublebuffer.png)

*图 5-3  双缓冲策略（设备与 CPU 交替使用两个缓冲区）*

- 单/双缓冲在通信中的区别：两台机器各设单缓冲区时，任一时刻只能单向传输；各设双缓冲区（发送缓冲+接收缓冲）时，同一时刻可实现双向传输。
- 循环缓冲区：将多个大小相等的缓冲区链接成循环队列，in 指针指向下一个可冲入的空缓冲区，out 指针指向下一个可取出的满缓冲区。

> **★ 重点**：缓冲池（必背）：系统共用的缓冲区，按使用状况分为空缓冲队列、输入队列（装满输入数据）、输出队列（装满输出数据）；按功能设四种工作缓冲区 hin（收容输入）、sin（提取输入）、hout（收容输出）、sout（提取输出）。

- 缓冲池工作流程：输入进程从空缓冲队列取一块作 hin，冲满后挂到输入队列；计算进程从输入队列取一块作 sin，读空后挂到空缓冲队列；计算进程要输出时从空缓冲队列取一块作 hout，冲满后挂到输出队列；输出进程从输出队列取一块作 sout，读空后挂回空缓冲队列。

#### 5.3.1 磁盘的结构 【熟练掌握】

#### 5.3.2 磁盘调度算法 【熟练掌握】

#### 定义
> **★ 重点**：一次磁盘读写时间三部分（必背）：寻找（寻道）时间 TS、延迟（旋转）时间 TR、传输时间 Tt。总平均存取时间 Ta = TS + 1/(2r) + b/(rN)。

**寻道时间 TS = s + m × n（s 为磁臂启动时间，m 为每跨越一个磁道耗时，n 为跨越磁道数）**

**平均延迟时间 TR = (1/2) × (1/r) = 1/(2r)（r 为转速，1/r 为转一圈时间，平均转半圈）**

**传输时间 Tt = (1/r) × (b/N) = b/(rN)（b 为读写字节数，N 为每磁道字节数）**

> **★ 重点**：重要结论：延迟时间和传输时间都与磁盘转速线性相关，转速是硬件固有属性，操作系统无法优化；操作系统只能通过磁盘调度算法影响寻道时间。

- 先来先服务 FCFS：按请求到达顺序调度。公平，请求集中时性能尚可；请求分散时寻道时间长、性能差。
- 最短寻道时间优先 SSTF：优先处理距当前磁头最近的磁道（贪心思想），每次寻道最短但总体未必最短。性能好、平均寻道短，但可能产生“饥饿”。

![图 5-5  最短寻道时间优先 SSTF](figures/ch5_sstf.png)

*图 5-5  最短寻道时间优先 SSTF*

- 扫描算法 SCAN（电梯算法）：磁头只在一个方向上移动并处理请求，只有到最外侧磁道才能改向。防止 SSTF 饥饿，但到达边缘才折返有浪费，且对各位置磁道响应频率不平均。
- LOOK 算法：SCAN 的改进，磁头移动方向上已无请求就立即改向，不必到最边缘。
- 循环扫描 C-SCAN：磁头只朝特定方向移动时处理请求，返回时直接快速移到起始端不处理任何请求。各位置磁道响应频率平均，但平均寻道时间比 SCAN 长。
- C-LOOK 算法：C-SCAN 的改进，磁头移动方向已无请求就立即返回，且只返回到有请求的位置即可。

![图 5-6  扫描算法 SCAN（电梯算法）](figures/ch5_scan.png)

*图 5-6  扫描算法 SCAN（电梯算法）*

> **★ 重点**：答题约定（必背）：题目无特别说明时，SCAN 就是 LOOK、C-SCAN 就是 C-LOOK（即不要求一定移动到最边缘磁道）。

| 算法 | 核心思想 | 优点 | 缺点/特点 |
| --- | --- | --- | --- |
| FCFS | 按到达顺序 | 公平 | 寻道时间长 |
| SSTF | 优先最近磁道（贪心） | 平均寻道短 | 可能饥饿 |
| SCAN | 单向扫描到边缘才折返 | 无饥饿、性能较好 | 边缘折返浪费、响应频率不平均 |
| C-SCAN | 单向处理、返回不处理 | 响应频率平均 | 平均寻道更长 |
| LOOK | 无请求即折返（SCAN 改进） | 寻道更短 | 同 SCAN 但更高效 |
| C-LOOK | 无请求即返回且只回有请求处 | 比 C-SCAN 更短 | 响应频率较平均 |

#### 💬 通俗理解
一句话：LOOK、C-SCAN 就是 C-LOOK（即不要求一定移动到最边缘磁道）。

#### 5.3.3 减少磁盘延迟时间的方法 【熟练掌握】

- 方法一·交替编号：让逻辑上相邻的扇区在物理上有一定间隔，减小读连续逻辑扇区的延迟。

- 方法二·错位命名：相邻盘面相对位置相同处的扇区编号错开，使读完一块、处理期间目标扇区正好转到磁头下方，可连续读取，减少延迟。

#### 5.3.4 磁盘的管理 【掌握】

#### 定义
- 磁盘初始化三步：①低级格式化（物理格式化）——将磁道划分为扇区，扇区含头、数据区（如 512B）、尾，头尾存放校验码（奇偶校验、CRC）等管理结构；②磁盘分区——每个分区由若干柱面组成（C/D/E 盘）；③逻辑格式化——创建文件系统根目录、初始化存储空间管理结构（位示图、空闲分区表）。
- 引导块：完整自举程序放在磁盘固定位置的引导块（启动分区），ROM 中只放很小的“自举装入程序”，开机先运行自举装入程序找到引导块，把完整自举程序读入内存完成初始化。拥有启动分区的磁盘叫启动磁盘/系统磁盘（C 盘）。
- 坏块管理：坏块是硬件故障，OS 无法修复只能标记。简单磁盘在逻辑格式化时检查并在 FAT 表标明坏块（对 OS 不透明）；复杂磁盘由磁盘控制器维护坏块链表、保留备用扇区替换坏块（扇区备用，对 OS 透明）。

#### 5.3.5 固态硬盘 SSD 【熟练掌握】

#### 定义
- SSD 基于闪存，无机械部件，速度远快于机械硬盘。
- SSD 结构：由若干闪存块组成，块大小 16KB~512KB；每个块由若干页组成，页大小 512B~4KB。SSD 按“页”读写，按“块”擦除。

> **★ 重点**：SSD 特性（必背）：读/写以页为单位，擦除以块为单位；写入前必须先擦除，且擦除次数有限（闪存块有寿命）；因此 SSD 需采用磨损均衡技术使各块擦除次数尽量均衡，延长寿命。

- SSD 寿命估算思路：总容量 ÷ 每天写入量 = 平均每天全盘写一遍所需天数；再乘每块可擦除次数即为最理想寿命天数。
