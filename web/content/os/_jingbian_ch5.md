# 第五章  输入输出管理

【考情速览】本章是操作系统五大功能之一，408 统考既考选择题也考大题（常与文件管理、进程管理综合）。高频考点集中在：I/O 设备分类、四种 I/O 控制方式（程序直接控制/中断驱动/DMA/通道）的对比、I/O 软件层次结构、设备独立性、SPOOLing 假脱机技术、设备分配与回收、缓冲区管理（单缓冲/双缓冲耗时计算）、磁盘结构与调度算法（FCFS/SSTF/SCAN/C-SCAN/LOOK 的寻道长度计算）、减少磁盘延迟、SSD。其中磁盘调度算法和缓冲耗时计算几乎每年必考一道计算，务必掌握公式与分步推导。

## 5.1 I/O 管理概述

### 5.1.1 I/O 设备的基本概念和分类

- “I/O”即输入/输出（Input/Output）。I/O 设备就是能将数据输入到计算机、或接收计算机输出数据的外部设备，属于计算机的硬件部件。鼠标、键盘是典型输入设备；显示器是输出设备；移动硬盘既可输入又可输出。
- UNIX 系统把外部设备抽象为一种特殊文件，用户可用与文件操作相同的方式（Read/Write）操作设备。

> **★ 重点**：设备分类三个维度（必背）：按使用特性分——人机交互类（鼠标/键盘/打印机，速度慢）、存储设备（磁盘/光盘，速度快）、网络通信设备（调制解调器，速度居中）。

| 分类依据 | 类别 | 典型设备 | 特点 |
| --- | --- | --- | --- |
| 按使用特性 | 人机交互类 | 鼠标、键盘、打印机 | 数据传输速度慢 |
| 按使用特性 | 存储设备 | 磁盘、光盘 | 数据传输速度快 |
| 按使用特性 | 网络通信设备 | 调制解调器 | 速度介于二者之间 |
| 按传输速率 | 低速设备 | 鼠标、键盘 | 每秒几个到几百字节 |
| 按传输速率 | 中速设备 | 激光打印机 | 每秒数千至上万字节 |
| 按传输速率 | 高速设备 | 磁盘 | 每秒数千字节至千兆字节 |
| 按信息交换单位 | 字符设备 | 鼠标、键盘 | 单位是字符，慢、不可寻址，常中断驱动 |
| 按信息交换单位 | 块设备 | 磁盘 | 单位是块，快、可寻址、可随机读写 |

> **★ 重点**：字符设备与块设备的本质区别：块设备以“块”为传输单位、传输速率高、可寻址（可随机读写任一块）；字符设备以“字符”为单位、传输慢、不可寻址、常用中断驱动方式。这是判断设备类型和选择 I/O 控制方式的关键依据。

### 5.1.2 I/O 控制器

- I/O 设备由机械部件和电子部件组成。机械部件执行具体 I/O 操作（如鼠标按钮、LED 屏、磁臂）；电子部件是 CPU 与机械部件之间的“中介”，称为 I/O 控制器（又称设备控制器）。
- CPU 无法直接控制机械部件，只能通过 I/O 控制器间接控制设备。

> **★ 重点**：I/O 控制器三组寄存器（必背）：数据寄存器（暂存输入/输出数据）、控制寄存器（存放 CPU 发来的命令和参数）、状态寄存器（记录设备当前状态，如 1 空闲、0 忙碌）。

- 为了区分控制器中的各个寄存器，要给每个寄存器设置地址。CPU 通过“地址”判断要读写哪个寄存器。
- 一个 I/O 控制器可能对应多个设备；数据/控制/状态寄存器都可能有多个，每个都要有地址。

| 编址方式 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 内存映像 I/O | 控制器寄存器与内存统一编址，占用内存地址的一部分 | 简化指令，可用内存操作指令操作控制器 | 占用内存地址空间 |
| 寄存器独立编址 | 控制器寄存器使用 I/O 专用地址，单独编址 | 不占用内存地址空间 | 需专门指令，还要指明控制器编号和寄存器地址 |

- I/O 控制器的组成：CPU 与控制器的接口（数据总线/地址线/控制线）、I/O 逻辑（负责地址译码、接收识别命令）、控制器与设备的接口（传送数据/状态/控制信息）。

### 5.1.3 I/O 控制方式

关注五个维度：①完成一次读写的流程；②CPU 干预频率；③数据传送单位；④数据流向；⑤主要优缺点。发展主线是“尽量减少 CPU 对 I/O 的干预”。

- 程序直接控制方式（关键词：轮询）：CPU 发出读指令后不断轮询状态寄存器，设备就绪后将数据寄存器内容读入 CPU 寄存器，再写入内存。每个字都需 CPU 帮助，CPU 长期忙等，利用率极低。
- 中断驱动方式（关键词：中断）：CPU 发出命令后即可切换其他进程，I/O 完成后控制器发出中断信号，CPU 在中断处理程序中读入一个字并写入主存。CPU 与设备可并行，但每个字仍经过 CPU，中断太频繁开销大。
- DMA 方式（Direct Memory Access，直接存储器存取）：以“块”为单位，数据直接从设备到内存（不经 CPU），仅在传送一个或多个连续块的开始和结束才需 CPU 干预，整块完成后才发中断。
- 通道控制方式（关键词：通道程序）：通道是“弱鸡版 CPU”，可识别并执行通道指令（通道程序放在主存，与 CPU 共享内存）。CPU 只发一次 I/O 指令指明通道程序位置和操作设备，之后通道自主完成一组数据块读写，完成后才发中断。

> **★ 重点**：DMA 控制器四个寄存器（必背）：DR 数据寄存器（暂存数据）、MAR 内存地址寄存器（输入时存目标内存地址/输出时存源地址）、DC 数据计数器（剩余字节数）、CR 命令/状态寄存器。

- DMA 限制：CPU 每发一条 I/O 指令只能读写一个或多个“连续”的数据块，且这些块在内存中也要连续；离散块需多次发指令、多次中断。

| 对比项 | 程序直接控制 | 中断驱动 | DMA | 通道控制 |
| --- | --- | --- | --- | --- |
| 完成方式 | CPU 不断轮询状态 | 设备完成发中断 | DMA 控制器传块后发中断 | 通道执行通道程序后发中断 |
| CPU 干预频率 | 极高 | 高 | 中 | 低 |
| 数据传送单位 | 字 | 字 | 块 | 一组块 |
| 数据流向 | 设备→CPU→内存 | 设备→CPU→内存 | 设备→内存（不经 CPU） | 设备→内存（通道控制） |
| 优点 | 实现简单 | CPU 与设备可并行 | 效率高、并行性好 | 资源利用率最高 |
| 主要缺点 | CPU 忙等、利用率低 | 中断频繁开销大 | 只能传连续块 | 实现复杂需专门硬件 |

### 5.1.4 I/O 软件层次结构

> **★ 重点**：I/O 软件四层（自上而下，必背顺序）：用户层软件 → 设备独立性软件 → 设备驱动程序 → 中断处理程序 → 硬件。越往上越接近用户，越往下越接近硬件，每层利用下层服务屏蔽细节向上层提供服务。

- 用户层软件：实现与用户交互的接口，提供库函数（如 printf），把用户请求翻译成格式化的 I/O 请求，通过系统调用请求内核服务。
- 设备独立性软件（又称设备无关性软件）：与硬件特性无关的功能几乎都在此层，六大功能见下条。

> **★ 重点**：设备独立性软件六大功能（必背）：①向上层提供统一调用接口（read/write）；②设备保护；③差错处理；④设备的分配与回收；⑤数据缓冲区管理；⑥建立逻辑设备名到物理设备名的映射（逻辑设备表 LUT），并按设备类型选择驱动程序。

- 逻辑设备表 LUT：记录“逻辑设备名 → 物理设备名 → 驱动程序入口地址”的映射。整系统一张 LUT（逻辑设备名不重复，适合单用户）；每个用户一张 LUT（逻辑设备名可重复，存于用户 PCB，适合多用户）。
- 设备驱动程序：把上层命令（read/write）转换成特定设备“听得懂”的操作，设置设备寄存器、检查设备状态。不同设备硬件特性不同（寄存器个数、状态位含义都不同），只有厂家知道，故厂家须提供对应驱动程序。
- 中断处理程序：I/O 完成后控制器发中断信号，系统按中断类型找到对应中断处理程序。流程：读设备状态 → 若正常则从设备读一个字经 CPU 放入内存缓冲区；若异常则做相应处理。

> **★ 重点**：层次归属判断技巧（高频考点）：直接涉及硬件具体细节、且与中断无关的操作 → 设备驱动程序层；不涉及硬件、对各类设备通用管理 → 设备独立性软件层；把用户请求翻译成系统调用 → 用户层软件。

### 5.1.5 应用程序接口与驱动程序接口

- 应用程序接口：设备独立性软件向上提供统一接口（read/write 系统调用），屏蔽设备差异。
- 阻塞 I/O：发出系统调用后进程转为阻塞态等待（如字符设备接口——键盘读字符 get）。
- 非阻塞 I/O：系统调用可迅速返回，进程无需阻塞等待（如块设备接口——写磁盘 write）。
- 驱动程序接口：不同操作系统对设备驱动程序接口的标准不同，设备厂商必须按操作系统的接口要求开发相应驱动，设备才能被使用。

## 5.2 I/O 核心子系统

### 5.2.1 I/O 核心子系统

- I/O 核心子系统即 I/O 软件的中间三层（设备独立性软件、设备驱动程序、中断处理程序）组成的内核部分。

> **★ 重点**：I/O 核心子系统重点功能（必背）：I/O 调度、设备保护、假脱机技术（SPOOLing）、设备分配与回收、缓冲区管理。其中 SPOOLing 因需请求磁盘设备的服务，一般在用户层软件实现。

- I/O 调度：用某种算法确定处理各 I/O 请求的顺序，如磁盘调度（FCFS/SSTF/SCAN/C-SCAN/LOOK/C-LOOK），打印机也可用 FCFS、优先级、短作业优先等。
- 设备保护：UNIX 中设备被看作特殊文件，每个设备有对应 FCB，系统根据 FCB 记录的信息判断用户访问权限，实现设备保护。

### 5.2.2 假脱机技术（SPOOLing）

- 脱机技术：批处理阶段用磁带（外围控制机控制）先收容慢速设备的数据，主机再从高速磁带读入，缓解 CPU 与慢速设备的速度矛盾；“脱机”即脱离主机控制进行的 I/O。
- 假脱机技术（SPOOLing）= 用软件方式模拟脱机技术，需要多道程序技术支撑，系统建立“输入进程”和“输出进程”。

> **★ 重点**：SPOOLing 系统组成（必背）：输入井/输出井（磁盘上开辟的存储区，输入井模拟脱机输入磁带、输出井模拟脱机输出磁带）、输入缓冲区/输出缓冲区（内存中的缓冲区）、输入进程/输出进程（分别模拟外围控制机）。

- 独占设备：一段时间只能满足一个进程请求（如打印机）；共享设备：宏观上可同时使用、微观上交替使用（如磁盘）。

> **★ 重点**：SPOOLing 核心作用（必背）：将一台物理设备虚拟成逻辑上的多台设备，把独占设备改造成共享设备（典型：共享打印机）。

- 共享打印机原理：多进程请求打印时系统并不真正分配打印机，而是由假脱机管理进程为每个进程在磁盘输出井中申请空闲缓冲区存数据、申请打印请求表挂到假脱机文件队列；打印机空闲时输出进程取队头请求表，把数据从输出井经输出缓冲区送到打印机。

### 5.2.3 设备的分配与回收

- 设备固有属性三类：独占设备（一个时段只分给一个进程）、共享设备（可同时分给多进程，宏观共享微观交替）、虚拟设备（用 SPOOLing 把独占设备改造成虚拟共享设备）。
- 设备分配算法：先来先服务、优先级高者优先、短任务优先等。

> **★ 重点**：安全分配方式 vs 不安全分配方式（必背）：安全分配——分配设备后即阻塞进程，I/O 完成才唤醒，破坏“请求和保持”条件不会死锁，但 CPU 与设备串行；不安全分配——分配后进程可继续执行并发新请求，CPU 与 I/O 可并行推进快，但可能死锁。

- 静态分配：进程运行前一次性分配全部资源，运行结束归还，破坏“请求和保持”不产生死锁；动态分配：运行过程中动态申请。
- 数据结构关系：一个通道控制多个控制器，一个控制器控制多个设备。

| 数据结构 | 作用 | 关键字段 |
| --- | --- | --- |
| 设备控制表 DCT | 每个设备一张，记录设备情况 | 设备类型、设备标识符、设备状态、指向控制器表指针、设备队列队首指针 |
| 控制器控制表 COCT | 每个控制器一张 | 控制器标识符、控制器状态、指向通道表指针、控制器队列首尾指针 |
| 通道控制表 CHCT | 每个通道一张 | 通道标识符、通道状态、控制器表首址、通道队列首尾指针 |
| 系统设备表 SDT | 记录系统中全部设备 | 设备类型、设备标识符、DCT、驱动程序入口 |

> **★ 重点**：设备分配步骤（必背）：①按物理设备名查 SDT → ②查 DCT，设备忙则 PCB 挂设备等待队列，否则分配 → ③查 COCT，控制器忙则挂起否则分配 → ④查 CHCT，通道忙则挂起否则分配。只有设备、控制器、通道三者都分配成功，这次分配才算成功。

- 改进：建立逻辑设备名→物理设备名映射（LUT），用户编程只需提供逻辑设备名（即设备类型），系统在 SDT 中找同类型空闲设备分配并新增 LUT 表项。

### 5.2.4 缓冲区管理

- 缓冲区是存储区域，可用硬件寄存器（成本高、容量小，如联想寄存器）或内存实现。本节讨论“内存作为缓冲区”。
- 缓冲区作用：①缓和 CPU 与 I/O 设备之间速度不匹配的矛盾；②减少对 CPU 的中断频率（字符设备每输出一个字符发一次中断）；③解决数据粒度不匹配（进程一次生成一块、设备一次输出一个字符）；④提高 CPU 与 I/O 之间的并行性。
- 单缓冲：主存分配一个缓冲区（默认为一个块大小）。缓冲区非空时不能冲入只能传出；为空时可冲入但必须充满才能传出。

> **★ 重点**：单缓冲处理一块数据平均耗时（必背公式）：Max(C, T) + M。其中 T 为设备输入一块数据的时间，M 为缓冲区数据传送到工作区的时间，C 为 CPU 处理一块数据的时间。

- 双缓冲：分配两个缓冲区。处理一块数据平均耗时为 Max(T, C+M)。

*图 5-3  双缓冲策略（设备与 CPU 交替使用两个缓冲区）*

- 单/双缓冲在通信中的区别：两台机器各设单缓冲区时，任一时刻只能单向传输；各设双缓冲区（发送缓冲+接收缓冲）时，同一时刻可实现双向传输。
- 循环缓冲区：将多个大小相等的缓冲区链接成循环队列，in 指针指向下一个可冲入的空缓冲区，out 指针指向下一个可取出的满缓冲区。

> **★ 重点**：缓冲池（必背）：系统共用的缓冲区，按使用状况分为空缓冲队列、输入队列（装满输入数据）、输出队列（装满输出数据）；按功能设四种工作缓冲区 hin（收容输入）、sin（提取输入）、hout（收容输出）、sout（提取输出）。

- 缓冲池工作流程：输入进程从空缓冲队列取一块作 hin，冲满后挂到输入队列；计算进程从输入队列取一块作 sin，读空后挂到空缓冲队列；计算进程要输出时从空缓冲队列取一块作 hout，冲满后挂到输出队列；输出进程从输出队列取一块作 sout，读空后挂回空缓冲队列。

## 5.3 磁盘与固态硬盘

### 5.3.1 磁盘的结构

- 磁盘表面由磁性物质组成，可记录二进制数据。盘面划分成一个个磁道（一个“圈”），磁道又划分成扇区，每个扇区就是一个“磁盘块”，各扇区存放数据量相同（如 1KB）。
- 最内侧磁道的扇区面积最小，数据密度最大。
- 一个盘片可能有两个盘面，每个盘面对应一个磁头；所有磁头连在同一个磁臂上，只能“共进退”。
- 所有盘面中相对位置相同的磁道组成柱面。

> **★ 重点**：磁盘物理地址 = （柱面号，盘面号，扇区号），可定位任意磁盘块。读块步骤：①按柱面号移动磁臂；②激活指定盘面对应磁头；③磁盘旋转使目标扇区划过磁头完成读写。

- 磁盘分类：磁头可移动=活动头磁盘（磁臂伸缩定位磁道），磁头不可移动=固定头磁盘（每磁道一个磁头）；盘片可换=可换盘磁盘，不可换=固定盘磁盘。

### 5.3.2 磁盘调度算法

> **★ 重点**：一次磁盘读写时间三部分（必背）：寻找（寻道）时间 TS、延迟（旋转）时间 TR、传输时间 Tt。总平均存取时间 Ta = TS + 1/(2r) + b/(rN)。

**寻道时间 TS = s + m × n（s 为磁臂启动时间，m 为每跨越一个磁道耗时，n 为跨越磁道数）**

**平均延迟时间 TR = (1/2) × (1/r) = 1/(2r)（r 为转速，1/r 为转一圈时间，平均转半圈）**

**传输时间 Tt = (1/r) × (b/N) = b/(rN)（b 为读写字节数，N 为每磁道字节数）**

> **★ 重点**：重要结论：延迟时间和传输时间都与磁盘转速线性相关，转速是硬件固有属性，操作系统无法优化；操作系统只能通过磁盘调度算法影响寻道时间。

- 先来先服务 FCFS：按请求到达顺序调度。公平，请求集中时性能尚可；请求分散时寻道时间长、性能差。
- 最短寻道时间优先 SSTF：优先处理距当前磁头最近的磁道（贪心思想），每次寻道最短但总体未必最短。性能好、平均寻道短，但可能产生“饥饿”。

![图 5-5  最短寻道时间优先 SSTF](figures/ch5_sstf.png)

*图 5-5  最短寻道时间优先 SSTF*

- 扫描算法 SCAN（电梯算法）：磁头只在一个方向上移动并处理请求，只有到最外侧磁道才能改向。防止 SSTF 饥饿，但到达边缘才折返有浪费，且对各位置磁道响应频率不平均。
- LOOK 算法：SCAN 的改进，磁头移动方向上已无请求就立即改向，不必到最边缘。
- 循环扫描 C-SCAN：磁头只朝特定方向移动时处理请求，返回时直接快速移到起始端不处理任何请求。各位置磁道响应频率平均，但平均寻道时间比 SCAN 长。
- C-LOOK 算法：C-SCAN 的改进，磁头移动方向已无请求就立即返回，且只返回到有请求的位置即可。

![图 5-6  扫描算法 SCAN（电梯算法）](figures/ch5_scan.png)

*图 5-6  扫描算法 SCAN（电梯算法）*

> **★ 重点**：答题约定（必背）：题目无特别说明时，SCAN 就是 LOOK、C-SCAN 就是 C-LOOK（即不要求一定移动到最边缘磁道）。

| 算法 | 核心思想 | 优点 | 缺点/特点 |
| --- | --- | --- | --- |
| FCFS | 按到达顺序 | 公平 | 寻道时间长 |
| SSTF | 优先最近磁道（贪心） | 平均寻道短 | 可能饥饿 |
| SCAN | 单向扫描到边缘才折返 | 无饥饿、性能较好 | 边缘折返浪费、响应频率不平均 |
| C-SCAN | 单向处理、返回不处理 | 响应频率平均 | 平均寻道更长 |
| LOOK | 无请求即折返（SCAN 改进） | 寻道更短 | 同 SCAN 但更高效 |
| C-LOOK | 无请求即返回且只回有请求处 | 比 C-SCAN 更短 | 响应频率较平均 |

### 5.3.3 减少磁盘延迟时间的方法

- 问题：磁头读完一个扇区后需一小段时间处理，而盘片不停旋转；若逻辑相邻扇区物理上也相邻，读连续逻辑扇区会等很久延迟。
- 方法一·交替编号：让逻辑上相邻的扇区在物理上有一定间隔，减小读连续逻辑扇区的延迟。

> **★ 重点**：磁盘地址结构为何是（柱面号，盘面号，扇区号）而非（盘面号，柱面号，扇区号）（必背）：读地址连续的块时，先变扇区号再变盘面号（同一柱面内）时无需移动磁头臂，只需激活相邻盘面磁头，可减少磁头移动时间。

- 方法二·错位命名：相邻盘面相对位置相同处的扇区编号错开，使读完一块、处理期间目标扇区正好转到磁头下方，可连续读取，减少延迟。

### 5.3.4 磁盘的管理

- 磁盘初始化三步：①低级格式化（物理格式化）——将磁道划分为扇区，扇区含头、数据区（如 512B）、尾，头尾存放校验码（奇偶校验、CRC）等管理结构；②磁盘分区——每个分区由若干柱面组成（C/D/E 盘）；③逻辑格式化——创建文件系统根目录、初始化存储空间管理结构（位示图、空闲分区表）。
- 引导块：完整自举程序放在磁盘固定位置的引导块（启动分区），ROM 中只放很小的“自举装入程序”，开机先运行自举装入程序找到引导块，把完整自举程序读入内存完成初始化。拥有启动分区的磁盘叫启动磁盘/系统磁盘（C 盘）。
- 坏块管理：坏块是硬件故障，OS 无法修复只能标记。简单磁盘在逻辑格式化时检查并在 FAT 表标明坏块（对 OS 不透明）；复杂磁盘由磁盘控制器维护坏块链表、保留备用扇区替换坏块（扇区备用，对 OS 透明）。

### 5.3.5 固态硬盘 SSD

- SSD 基于闪存，无机械部件，速度远快于机械硬盘。
- SSD 结构：由若干闪存块组成，块大小 16KB~512KB；每个块由若干页组成，页大小 512B~4KB。SSD 按“页”读写，按“块”擦除。

> **★ 重点**：SSD 特性（必背）：读/写以页为单位，擦除以块为单位；写入前必须先擦除，且擦除次数有限（闪存块有寿命）；因此 SSD 需采用磨损均衡技术使各块擦除次数尽量均衡，延长寿命。

- SSD 寿命估算思路：总容量 ÷ 每天写入量 = 平均每天全盘写一遍所需天数；再乘每块可擦除次数即为最理想寿命天数。

## 经典例题

**【例题】** （磁盘调度综合）某磁盘磁道 0~200，磁头初始位于 100 号磁道，正向磁道号增大方向移动。请求序列：55、58、39、18、90、160、150、38、184。分别用 FCFS、SSTF、SCAN、C-SCAN 计算磁头移动总磁道数。

**解：** ①FCFS：按请求顺序移动。|100−55|=45，|55−58|=3，|58−39|=19，|39−18|=21，|18−90|=72，|90−160|=70，|160−150|=10，|150−38|=112，|38−184|=146，总计 45+3+19+21+72+70+10+112+146=498 个磁道。②SSTF：每次选最近。100→90(10)→58(32)→55(3)→39(16)→38(1)→18(20)→150(132)→160(10)→184(24)，总计 248 个磁道。③SCAN：先向增大方向扫到最外侧 200 再折返。100→150→160→184→200→90→58→55→39→38→18，移动 (200−100)+(200−18)=282 个磁道。④C-SCAN：向增大方向处理到 200，返回 0 不处理，再从 0 向增大方向处理到 90。移动 (200−100)+(200−0)+(90−0)=390 个磁道。注意：题目未特别说明时 SCAN/C-SCAN 默认到最边缘磁道，若默认 LOOK/C-LOOK 则分别为 250、322 个磁道。

**【例题】** （双缓冲耗时）设 T 为设备输入一块数据的时间，M 为缓冲区数据传送到工作区的时间，C 为 CPU 处理一块数据的时间。若 T=100μs、M=10μs、C=50μs，求单缓冲和双缓冲处理一块数据的平均耗时。

**解：** 单缓冲耗时 = Max(C,T)+M = Max(50,100)+10 = 100+10 = 110μs。双缓冲耗时 = Max(T, C+M) = Max(100, 50+10) = Max(100,60) = 100μs。本例中 T 最大，双缓冲瓶颈在设备输入，CPU 与设备可充分并行。若改为 T=40μs、C=50μs、M=10μs，则单缓冲=Max(50,40)+10=60μs，双缓冲=Max(40,60)=60μs。

**【例题】** （磁盘存取时间）某硬盘转速 7200 转/分，每磁道 100KB，磁臂启动时间 2ms，每跨越一个磁道 0.2ms。现要随机读取 50KB 数据，平均寻道需跨越 20 条磁道，求平均存取时间。

**解：** 转速 r = 7200/60 = 120 转/秒。寻道时间 TS = s + m×n = 2 + 0.2×20 = 6ms。平均延迟 TR = 1/(2r) = 1/(2×120) = 1/240 s ≈ 4.17ms。传输时间 Tt = b/(rN) = 50KB/(120×100KB) = 50/12000 s ≈ 4.17ms。总平均存取时间 Ta = 6 + 4.17 + 4.17 ≈ 14.34ms。

**【例题】** （I/O 方式判断）下列场景分别应采用哪种 I/O 控制方式：①鼠标点击的输入；②从磁盘连续读取一个文件；③需要 CPU 和大量外设并行工作的大型服务器；④极简单的单片机外设轮询。

**解：** ①鼠标是字符设备、速率慢，采用中断驱动方式；②磁盘是块设备且连续传送，采用 DMA 方式；③大型服务器希望 CPU 从 I/O 中最大程度解脱、资源利用率最高，采用通道控制方式；④单片机资源有限、实现要简单，采用程序直接控制方式（轮询）。判断口诀：字符慢设备用中断、块设备用 DMA、极致并行用通道、追求简单用轮询。

**【例题】** （SSD 寿命）某 SSD 总容量 1TB，闪存块可擦写 1K 次，用户平均每天写入 128GB，采用磨损均衡技术，求最理想情况下可用多久。

**解：** 1TB ÷ 128GB = 8，即平均每 8 天每个闪存块被擦除一次（磨损均衡使擦除完全均匀）。每块可擦 1K 次，故可用 8×1K = 8K 天 ≈ 8000/365 ≈ 21.9 年，约 22~23 年。思路：寿命天数 =（总容量 ÷ 每天写入量）× 每块可擦次数。

**【例题】** （单缓冲推导）采用单缓冲，设备每 T 时间输入一块、缓冲区到工作区传送需 M、CPU 处理需 C。请说明为何处理一块平均耗时是 Max(C,T)+M。

**解：** 设初始状态为工作区满、缓冲区空。缓冲区为空可立即开始冲入，设备需 T 时间充满缓冲区；此后需 M 时间把缓冲区内容传送到工作区。当 T>C 时，CPU 早已处理完上一块，但必须等设备 T 充满缓冲区，故周期为 T+M；当 T<C 时，缓冲区 T 充满后 CPU 还没处理完上一块，必须等 CPU 处理完（再花 C）才能传送，故周期为 C+M。两种情况取最大，即 Max(C,T)+M。

**【例题】** （SCAN 饥饿与 LOOK）为何 SCAN 不会产生 SSTF 那样的饥饿？LOOK 相比 SCAN 改进在哪？

**解：** SSTF 可能因磁头在小区域内来回移动而饿死远端请求。SCAN 规定磁头只沿一个方向移动处理请求，只有到达最外侧才折返，因此远端磁道也会被陆续服务，不会饥饿。LOOK 的改进是：磁头移动方向上已无请求就立即折返，不必移到最边缘磁道，从而进一步缩短寻道时间。

## 易错点速记

- 字符设备不可寻址、块设备可寻址；鼠标键盘是字符设备，磁盘是块设备，别记反。
- 内存映像 I/O 是“寄存器与内存统一编址”，寄存器独立编址是“I/O 专用地址”，前者简化指令、后者需专门指令。
- 中断驱动方式数据仍要“设备→CPU→内存”，只有 DMA 和通道才“设备→内存”不经 CPU，别以为中断方式数据不经过 CPU。
- DMA 每次只能读写“连续”的数据块且内存中也要连续；离散块必须多次发指令，这是 DMA 的主要缺点。
- 设备独立性软件是“与硬件无关”的通用管理，设备驱动程序是“与硬件相关”的具体控制，判断层次时先看是否涉及硬件细节。
- SPOOLing 的输入井/输出井在“磁盘”上，输入缓冲区/输出缓冲区在“内存”中，两者位置别混淆。
- 安全分配方式破坏“请求和保持”故不产生死锁，不安全分配方式可能死锁，二者以“分配后是否阻塞进程”区分。
- 单缓冲耗时是 Max(C,T)+M，双缓冲耗时是 Max(T,C+M)，两个公式的 M 位置不同，务必分清再代入。
- 磁盘调度中“平均寻道长度”= 总移动磁道数 ÷ 请求个数，计算移动量时用磁道号差值的绝对值累加。
- SCAN/C-SCAN 默认要走到最边缘磁道才折返；LOOK/C-LOOK 无请求即折返。题目无特别说明时 SCAN 按 LOOK、C-SCAN 按 C-LOOK 处理。
- 磁盘平均延迟时间 TR=1/(2r) 只与转速有关，操作系统无法优化；操作系统只能优化寻道时间（通过调度算法）。
- 磁盘物理地址是（柱面号，盘面号，扇区号），先柱面后盘面；顺序读连续块时先变盘面号再变柱面号可少移动磁头。
- SSD 以“页”为单位读写、以“块”为单位擦除，写前须擦除且擦除次数有限，故用磨损均衡延长寿命。
