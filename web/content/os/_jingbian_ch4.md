# 第四章  文件管理

【考情速览】本章是操作系统选择题与综合题的高频来源。核心考点：文件的逻辑结构（顺序/索引/索引顺序及平均查找次数）、文件目录（FCB、索引结点、树形目录、目录项查找磁盘 I/O 次数）、文件的物理结构（连续/链接/索引分配及其随机访问能力、最大文件长度、读盘次数）、文件存储空间管理（空闲表/空闲链表/位示图/成组链接，重点是位示图的盘块号与字号位号换算）、文件共享（硬链接/软链接）、文件保护（口令/加密/访问控制）。综合题常考混合索引计算与位示图计算，务必掌握可套用公式并熟练分步求解。

## 4.1 初识文件管理

### 文件的基本概念与属性

- 文件：一组有意义的信息/数据集合，是文件系统中最基本的数据管理单位。按是否有结构分为无结构文件（流式文件，如 .txt）和有结构文件（记录式文件，如数据库表）。
- 文件属性：文件名（用户可见，同一目录下不允许重名）、标识符（系统内部唯一编号，对用户无读性）、类型、位置（路径供用户用，外存地址供 OS 用且对用户不可见）、大小、创建/修改时间、所有者、保护信息。

> **★ 重点**：按名存取：用户通过文件名访问文件，操作系统通过文件目录（FCB）实现文件名到文件物理位置的映射。

- 文件内部数据的组织（记录之间如何排列）是“逻辑结构”问题；文件之间如何组织（目录/文件夹）是“目录”问题；文件数据如何存放在外存是“物理结构”问题；空闲磁盘块如何管理是“存储空间管理”问题。

## 4.2 文件的逻辑结构

### 4.2.1 无结构文件与有结构文件

- 无结构文件（流式文件）：由二进制流或字符流组成，如 .txt，无记录概念，不讨论逻辑结构。
- 有结构文件（记录式文件）：由一组相似记录组成，每条记录又由若干数据项组成；其中可标识不同记录的数据项称为关键字。
- 按记录长度是否相等分为定长记录（每条记录长度相同）与可变长记录（长度不定）。

### 4.2.2 顺序文件

- 顺序文件：记录在逻辑上一个接一个顺序排列，记录可定长也可变长，物理上可顺序存储（类似顺序表）或链式存储（类似链表）。

> **★ 重点**：定长记录 + 物理上顺序存储的顺序文件，既能随机存取（直接算出第 i 个记录地址），又能按关键字快速检索；可变长记录的顺序文件只能从头顺序查找。

- 定长记录第 i 个记录的逻辑地址 = i × L（L 为记录长度）；可变长记录因记录长度不显式已知，无法直接定位。
- 缺点：增加/删除一个记录较困难（尤其需保持有序时）。考试默认“顺序文件”指物理上顺序存储。

### 4.2.3 索引文件

- 为每个记录建立一张索引表，每记录对应一个索引项（索引号、长度、指针），索引表本身是定长记录的顺序文件，因此可快速定位到第 i 个记录，支持随机存取与快速检索。
- 可用不同数据项建立多张索引表（如按学号、按姓名），加快按不同关键字检索；增加/删除记录只需修改索引表。
- 缺点：每个记录都占一个索引项，文件记录较小（如 8B）而索引项较大（如 32B）时，索引表可能比数据还大，空间利用率低。

### 4.2.4 索引顺序文件

- 索引顺序文件 = 索引文件 + 顺序文件的结合：一组记录对应一个索引项（分组），组内为顺序文件。

**N 个记录分 √N 组，每组 √N 个，检索一个记录平均查找次数 = √N/2 + √N/2 = √N（约）**

- 例：10000 个记录，分 100 组，每组 100 个，平均查找 50+50 = 100 次；多级索引顺序文件可进一步降低查找次数。

**为 N 个记录建立 K 级索引，最优分组为每组 N^(1/(K+1)) 个记录，平均查找次数 = (N^(1/(K+1))/2) × (K+1)**

- 例：10^6 个记录建 2 级索引，最优每组 10^(6/3)=100 个，平均查找 (100/2)×3 = 150 次。

| 逻辑结构 | 能否随机存取 | 检索方式 | 典型缺点 |
| --- | --- | --- | --- |
| 顺序文件（定长+顺序存储） | 能 | 可折半/顺序查找 | 增删记录困难 |
| 顺序文件（可变长） | 否 | 只能顺序查找 | 查找慢 |
| 索引文件 | 能 | 查索引表快速定位 | 索引表大，占空间 |
| 索引顺序文件 | 能（分组） | 先查索引再查组内 | 组内仍需顺序查找 |

## 4.3 文件目录

### 4.3.1 文件控制块 FCB

- 目录本身是一种有结构文件，由一条条记录（目录项）组成；一个 FCB 就是一个目录项。FCB 的有序集合称为文件目录。
- FCB 包含：基本信息（文件名、物理地址、逻辑/物理结构等）、存取控制信息（是否可读写、禁止访问名单等）、使用信息（建立/修改时间等）。

> **★ 重点**：FCB 中最重要的字段是“文件名”和“文件存放的物理地址”，二者实现按名存取。

- 目录操作：搜索、创建文件（新增目录项）、删除文件（删目录项）、显示目录、修改目录（如重命名）。

### 4.3.2 目录结构（单级 / 两级 / 树形 / 无环图）

- 单级目录：全系统一张目录表，实现按名存取但不允许重名，不适用于多用户系统。
- 两级目录：主文件目录 MFD + 用户文件目录 UFD，允许不同用户文件重名，可实现访问限制，但用户不能对自己的文件分类，缺乏灵活性。
- 多级目录（树形目录）：层次清晰、可分类、可重名、易保护；访问文件需用路径名，从根出发为绝对路径，从当前目录出发为相对路径。

> **★ 重点**：按绝对路径检索文件：每经过一级目录就要读一次磁盘（读入该级目录表）；设置“当前目录”用相对路径可减少磁盘 I/O 次数。

- 无环图目录结构：在树形目录上增加指向同一节点的有向边，方便多用户共享文件/目录；每个共享节点设共享计数器，删除时计数器减 1，减到 0 才真正删除。
- 共享文件 ≠ 复制文件：共享时系统中只有一份数据，任一用户修改全体可见；复制则有多个独立副本。

### 4.3.3 索引结点（FCB 的改进）

- 检索目录时只需用到“文件名”，故把除文件名外的描述信息放到索引结点，目录项只保留文件名 + 索引结点指针，使目录表“瘦身”。

> **★ 重点**：目录项瘦身后，每个盘块可容纳更多目录项，检索目录需读入的磁盘块数减少，显著提升检索速度。

- 例：FCB 64B、盘块 1KB 时每块存 16 个 FCB，640 个目录项需 40 块，平均检索 320 项、20 次 I/O；改用索引结点后（文件名 14B + 指针 2B）每块存 64 项，平均仅需 320/64 = 5 次 I/O。
- 外存中的叫磁盘索引结点，调入内存后叫内存索引结点（增加“是否被修改”“访问进程数”等信息）。

## 4.4 文件的物理结构（文件分配方式）

### 4.4.1 文件块与磁盘块

- 外存按“块/磁盘块/物理块”划分，每块含 2 的整数次幂个地址（如 1KB）；OS 以块为单位为文件分配空间，即使文件只有 10B 也占 1 块。
- 文件逻辑地址表示为（逻辑块号，块内地址），OS 负责把逻辑地址映射为物理地址（物理块号，块内地址），块内地址保持不变。

### 4.4.2 连续分配

- 要求每个文件占有一组连续的磁盘块；目录项记录起始块号和文件长度。

**物理块号 = 起始块号 + 逻辑块号（需先检查逻辑块号是否 < 文件长度）**

> **★ 重点**：连续分配支持顺序访问和随机访问，且顺序读/写时速度最快（磁头移动少）；但文件不便拓展、易产生磁盘碎片、存储空间利用率低（可用紧凑处理但代价大）。

### 4.4.3 链接分配（隐式链接）

- 离散分配，除最后一个盘块外每个盘块存指向下一盘块的指针（对用户透明）；目录项记录起始块号、结束块号。

> **★ 重点**：隐式链接只支持顺序访问，不支持随机访问；访问第 i 号逻辑块需依次读入前 i 块，共 i+1 次磁盘 I/O。

- 优点：方便拓展、无外部碎片、外存利用率高；缺点：只能顺序访问、查找效率低、指针占少量空间。

### 4.4.4 链接分配（显式链接 / FAT）

- 把链接各物理块的指针显式存放在文件分配表 FAT 中；一个磁盘只设一张 FAT，开机时读入内存常驻。目录项只需记录起始块号。

> **★ 重点**：显式链接（FAT）支持随机访问：查内存中的 FAT 即可完成逻辑块号到物理块号的转换，无需访问磁盘，访问速度远高于隐式链接。

- FAT 各表项物理连续、长度相同，故“物理块号”字段可隐含；文件拓展方便、无碎片，缺点是要占用一定存储空间。

### 4.4.5 索引分配

- 为每个文件建立一张索引表，记录各逻辑块对应的物理块（类似页表）；索引表所在盘块称索引块，文件数据所在盘块称数据块。目录项记录索引块号。

> **★ 重点**：索引表是一个文件一张；FAT 是一个磁盘一张。索引分配支持随机访问、便于拓展，但索引表占空间，访问数据前要先读入索引块。

- 单个索引块容量有限（如块 1KB、索引项 4B 时一块只能存 256 项），文件超过该块数时用三种方案解决：链接方案、多层索引、混合索引。
- ① 链接方案：多个索引块用指针链接；访问最后一个索引块需顺序读入前面所有索引块，I/O 次数多、效率低。
- ② 多层索引：类似多级页表，第一层索引块指向第二层索引块，可继续建第三、四层。

**采用 K 层索引且顶级索引表未调入内存时，访问一个数据块需 K+1 次读盘；K 层索引的最大文件长度 = 256^K × 块大小（块 1KB、索引项 4B）**

- 例：两层索引最大长度 = 256×256×1KB = 64MB；三层索引 = 256^3×1KB = 16GB。各级索引表大小不能超过一个磁盘块。
- ③ 混合索引：顶级索引表中同时含直接地址、一级间接索引、二级间接索引，小文件访问更快。

## 4.5 逻辑结构 VS 物理结构

- 逻辑结构从用户视角看文件内部数据如何组织（顺序/索引/索引顺序）；物理结构从 OS 视角看数据如何存放于外存（连续/链接/索引分配）。

> **★ 重点**：两个“随机访问”含义不同：逻辑结构支持随机访问 = 能根据记录号直接算出该记录的逻辑地址（定长记录顺序文件）；物理结构支持随机访问 = 能直接由逻辑块号得到物理块号（连续、显式链接 FAT、索引分配）。

- 顺序文件内部记录可顺序存储或链式存储；文件整体用连续/链接/索引分配由 OS 决定，二者独立。记录链式存储是用户自己设计，文件链接分配是 OS 决定。
- 索引文件的索引表由用户建立，映射“关键字 → 记录逻辑地址”；索引分配的索引表由 OS 建立，映射“逻辑块号 → 物理块号”。

| 物理结构 | 目录项关键内容 | 随机访问 | 文件拓展 | 碎片/空间 |
| --- | --- | --- | --- | --- |
| 连续分配 | 起始块号 + 长度 | 支持（且顺序最快） | 不便 | 有碎片、利用率低 |
| 隐式链接 | 起始块号 + 结束块号 | 不支持（i 块需 i+1 次 I/O） | 方便 | 无碎片、利用率高 |
| 显式链接 FAT | 起始块号 | 支持（查内存 FAT） | 方便 | 无碎片、占 FAT 空间 |
| 索引分配 | 索引块号 | 支持（先读索引块） | 方便 | 无碎片、索引表占空间 |

## 4.6 文件存储空间管理

### 4.6.1 存储空间的划分与初始化

- 先把物理磁盘划分为文件卷（逻辑卷/逻辑盘，如 C 盘、D 盘）；再对每个文件卷逻辑格式化，划分为目录区（存 FCB、空间管理信息）和文件区（存文件数据）。
- 学习存储空间管理从三方面入手：用什么方式记录空闲块、如何分配、如何回收。

### 4.6.2 空闲表法

- 用一张表记录连续空闲区（第一个空闲盘块号 + 空闲盘块数），适用于连续分配。
- 分配：类似动态分区分配，可用首次适应、最佳适应、最坏适应等算法为文件分配连续空间；回收：注意相邻空闲区合并（四种情况：前后均无、前后均有、前有、后有）。

### 4.6.3 空闲链表法（空闲盘块链 / 空闲盘区链）

- 空闲盘块链：每个空闲盘块存指向下一个空闲盘块的指针；分配从链头摘 K 块，回收挂链尾。适用于离散分配。
- 空闲盘区链：连续空闲块组成盘区，第一个盘块记录盘区长度和下一盘区指针；分配用首次/最佳适应检索，回收相邻盘区要合并。离散、连续分配都适用，效率更高。

### 4.6.4 位示图法

- 每个二进制位对应一个盘块（0 空闲、1 已分配），位示图用连续的“字”表示，可用（字号，位号）定位盘块。连续、离散分配都适用。

> **★ 重点**：位示图公式（从 0 开始，字长 n）：盘块号 b = n×i + j；反推字号 i = b/n、位号 j = b%n。若从 1 开始：b = n×(i-1) + j，i = (b-1)/n + 1，j = (b-1)%n + 1。务必先看清编号从 0 还是从 1 开始。

- 分配：扫描位示图找 K 个 0，换算盘块号分配给文件，把对应位置 1；回收：由盘块号算字号位号，把对应位置 0。

### 4.6.5 成组链接法（UNIX）

- 空闲表法/空闲链表法在大型文件系统中表/链过长，UNIX 用成组链接法：把空闲块分组，目录区专门用一个“超级块”记录第一组空闲块信息，系统启动时读入内存。
- 分配：从超级块第一组取空闲块，若该组用完则把下一组信息复制进超级块；回收：块数未满则加入超级块组，满则把超级块内容复制到新回收块、让新块成为第一组。

> **★ 重点**：成组链接法兼具空闲表法与空闲链表法的优点，能快速分配/回收大量空闲块，适合大型文件系统。

## 4.7 文件的基本操作

- 创建文件（create）：在外存找空闲空间，并在目标目录创建目录项（文件名 + 存放位置等）。
- 删除文件（delete）：按路径找目录项，回收文件占用盘块（依空闲表/链表/位示图策略处理），删除目录项。
- 打开文件（open）：按路径找目录项并检查权限，把目录项复制到内存“打开文件表”，返回编号（文件描述符）；之后用文件描述符操作文件，无需再查目录。
- 关闭文件（close）：删除进程打开文件表对应表项，回收内存资源，系统打开文件表计数器减 1，减到 0 才删表项。
- 读文件（read）/写文件（write）：用文件描述符指明文件，从读/写指针处读入/写出指定大小数据。

> **★ 重点**：打开文件并不把文件数据读入内存；系统打开文件表全局一张，记录“打开计数器”；Windows 提示“文件正在使用无法删除”就是检查了该计数器。

## 4.8 文件共享

### 4.8.1 基于索引结点的共享（硬链接）

- 多个用户目录项指向同一索引结点，索引结点设链接计数 count 表示被几个目录项链接。

> **★ 重点**：硬链接：删除文件时只删用户目录项并把 count 减 1，count > 0 时不能删文件数据（否则指针悬空），count = 0 才真正删除文件。

- 硬链接中多个文件名指向同一份文件数据，任一处修改处处可见。

### 4.8.2 基于符号链的共享（软链接）

- 新建一个 Link 类型文件（类似 Windows 快捷方式），内容记录目标文件路径；访问 Link 文件时按路径层层查找目录，最终找到目标文件索引结点。

> **★ 重点**：软链接（符号链）：目标文件被删除后 Link 文件仍存在，但按路径找不到目标（悬空链接）；软链接可指向目录，且 Link 文件名可与目标不同。

| 对比项 | 硬链接 | 软链接（符号链） |
| --- | --- | --- |
| 本质 | 多个目录项指向同一索引结点 | Link 文件记录目标路径 |
| 计数机制 | count 减到 0 才删文件 | 无计数，目标删后 Link 悬空 |
| 能否跨文件系统/指向目录 | 一般不能 | 可以 |
| 典型例子 | 同一索引结点多目录项 | Windows 快捷方式 |

## 4.9 文件保护

### 4.9.1 口令保护

- 为文件设口令存于 FCB/索引结点，访问前比对口令。优点：空间、时间开销小；缺点：口令存于系统内部，不够安全。

### 4.9.2 加密保护

- 用密码对文件加密，访问需正确密码解密（如异或加密）。优点：保密性强、不需在系统存储密码；缺点：加解密耗时。

### 4.9.3 访问控制

- 在 FCB/索引结点中增加访问控制列表 ACL，记录各用户可执行的操作（读/写/执行/添加/删除等）。
- 用户多时 ACL 很大，可用精简访问列表按“组”（系统管理员、文件主、文件主的伙伴、其他用户）标记权限；对某目录的控制要同样作用于其下所有文件。

## 4.10 文件系统层次结构

- 自上而下（用户接口到设备）：用户接口 → 文件目录系统 → 存取控制模块 → 逻辑文件系统与文件信息缓冲区 → 物理文件系统 → 辅助分配模块 → 设备管理模块 → 设备。
- 各层职责：用户接口处理 read/write/open/close 系统调用；文件目录系统按路径找 FCB/索引结点、管理目录与打开文件表；存取控制模块验证权限；逻辑文件系统把记录号转成逻辑地址；物理文件系统把逻辑地址转成物理地址；辅助分配模块负责空间分配回收；设备管理模块负责设备分配、缓冲区、磁盘调度、启动/释放设备。

> **★ 重点**：记忆方法（删除文件最后 100 条记录的例子）：用户接口 → 文件目录系统（找目录项）→ 存取控制（验权限）→ 逻辑文件系统（记录号转逻辑地址）→ 物理文件系统（逻辑转物理地址）→ 设备管理（发磁盘请求）→ 辅助分配（回收盘块）。

## 4.11 文件系统布局

- 磁盘从原始到可用依次：物理格式化（低级格式化，划分扇区、检测并替换坏扇区）→ 磁盘分区（分卷）→ 逻辑格式化（初始化文件系统）。
- 外存结构：主引导记录 MBR（含分区表）→ 引导块（启动时装入并运行）→ 超级块（文件系统关键信息）→ 空闲空间管理信息 → 索引结点 → 根目录 → 其余文件和目录。
- 内存结构：内存中维护分区表、目录缓存（近期访问的目录）、系统打开文件表、进程打开文件表等，用于加快检索与读写。

## 4.12 虚拟文件系统与文件系统挂载

- 虚拟文件系统（VFS）向上层提供统一标准的系统调用接口，屏蔽底层不同文件系统的实现差异；要求下层文件系统必须实现规定的函数（open/read/write 等）。

> **★ 重点**：vnode 只存在于主存中；inode（索引结点）既会被调入主存也会存于外存。每打开一个文件，VFS 在主存新建一个 vnode，用统一结构表示文件，功能指针指向具体文件系统的实现。

- 文件系统挂载（mounting）：①在 VFS 中注册新文件系统（内存挂载表记录类型、容量等）；②向 VFS 提供函数地址列表；③把新文件系统挂到挂载点（某父目录下）。

## 经典例题

**【例题】** （混合索引计算）某文件系统盘块大小 1KB，索引项 4B。某文件索引结点中含 8 个直接地址、1 个一级间接、1 个二级间接，顶级索引表已调入内存。求：①该文件最大长度；②访问第 6 号、第 100 号、第 10000 号逻辑块各需几次读盘。

**解：** ① 每块可存索引项 = 1KB/4B = 256 个。直接地址 8 块；一级间接 256 块；二级间接 256×256 = 65536 块。最大长度 = 8+256+65536 = 65800 块 = 65800KB。
② 逻辑块号范围：0~7 直接地址，8~263 一级间接，264~65799 二级间接。顶级索引表已调入内存时，读盘次数 = 读数据块前还需读的间接索引块数 + 1（数据块）：第 6 号（直接）→ 1 次；第 100 号（一级间接，读 1 次间接块）→ 2 次；第 10000 号（二级间接，读 2 次间接块）→ 3 次。若顶级索引表未调入内存，则各再加 1 次（先读顶级索引表）。

**【例题】** （位示图计算）某磁盘有 3000 个盘块，位示图用字长为 32 位的字表示，盘块号、字号、位号均从 0 开始。求：①盘块号 2017 对应的字号和位号；②第 20 字第 5 位对应哪个盘块。

**解：** ① 字号 i = 2017/32 = 63（商），位号 j = 2017%32 = 1，即（63, 1）。
② 盘块号 b = n×i + j = 32×20 + 5 = 645。
公式：b = n×i + j；i = b/n，j = b%n（从 0 开始）。若从 1 开始：b = n×(i-1)+j。

**【例题】** （FAT 显式链接）某文件 aaa 依次占用磁盘块 2 → 5 → 0 → 1（FAT 常驻内存），目录项记录起始块号 2。问：访问第 3 个逻辑块（逻辑块号 2）需要几次读磁盘操作？

**解：** 显式链接的块号转换在内存中查 FAT 完成，不需读盘。逻辑块号 0 对应物理块 2，逻辑块号 1 对应 5，逻辑块号 2 对应 0；找到物理块 0 后只需读该数据块 1 次，故共 1 次读盘。对比：若为隐式链接，则需依次读 2、5、0 三块，共 3 次。

**【例题】** （目录项查找）某目录共有 640 个目录项。若 FCB 64B、盘块 1KB，求按文件名检索平均需读几次磁盘；若改用索引结点（文件名 14B + 指针 2B）又是几次？

**解：** FCB 方案：每块存 1KB/64B = 16 个 FCB，640 项占 40 块，平均检索 320 项、读 320/16 = 20 块 → 20 次。索引结点方案：每项 16B，每块存 1024/16 = 64 项，平均读 320/64 = 5 块 → 5 次。结论：目录项瘦身显著减少磁盘 I/O。

**【例题】** （多层索引最大长度）某文件系统盘块 1KB、索引项 4B，采用三层索引。求文件最大长度及访问一个数据块的最多读盘次数（顶级索引表未调入内存）。

**解：** 每块存 256 个索引项。最大长度 = 256×256×256×1KB = 16GB。三层索引（K=3）且顶级未调入内存，读盘 = K+1 = 4 次（读一级、二级、三级索引块各 1 次 + 读数据块 1 次）。

**【例题】** （索引顺序文件）某顺序文件有 10000 条记录，采用索引顺序文件结构，每组记录数相同。求检索一个记录的平均查找次数。

**解：** 分 √10000 = 100 组，每组 100 条。先顺序查索引表找分组平均 50 次，再在组内顺序查平均 50 次，共 50+50 = 100 次。若建 2 级索引（10^4 记录），最优每组 10^(4/3)≈22 个，平均查找 (22/2)×3 ≈ 33 次，效率进一步提升。

## 易错点速记

- “随机访问”两个层次别混：逻辑结构看能否由记录号直接算逻辑地址；物理结构看能否由逻辑块号直接得物理块号（连续、FAT、索引分配可随机，隐式链接不可）。
- 隐式链接访问第 i 号逻辑块需 i+1 次读盘；显式链接（FAT）块号转换在内存完成，只读 1 次数据块。
- 索引表“一个文件一张”，FAT“一个磁盘一张”；索引结点 inode 内存外存都有，vnode 只在内存。
- 位示图换算务必先看清盘块号/字号/位号从 0 还是从 1 开始，王道书默认从 1 开始（b = n×(i-1)+j）。
- 硬链接 count 减到 0 才删数据；软链接目标被删后 Link 文件仍在但路径失效（悬空）。
- K 层索引访问数据块读盘 K+1 次的前提是“顶级索引表未调入内存”，若已调入则减 1；多层索引最大长度 = 256^K × 块大小（每块 256 项）。
- 口令保护密码存在系统内不够安全；加密保护密码不存系统但加解密耗时——两者优缺点别记反。
- “链接分配”未注明显式/隐式时默认按隐式链接处理。
