# 第一章  计算机系统概述

【考情速览】本章是操作系统入门章，408 统考以选择题为主（偶在综合题中结合考查）。高频考点集中在：操作系统的概念与功能、四大特征（并发/共享/虚拟/异步）及其关系、内核态与用户态、特权指令、中断与异常的分类、系统调用的过程、操作系统体系结构（宏内核/微内核）以及引导与虚拟机。其中“并发与并行”“内中断与外中断”“大内核与微内核”“系统调用过程”几乎是每年必考。

## 1.1 操作系统的概念与功能

### 1.1.1 操作系统的概念

- 操作系统（Operating System, OS）是指控制和管理整个计算机系统的硬件和软件资源，并合理地组织调度计算机的工作和资源的分配，以提供给用户和其他软件方便的接口和环境的程序集合。

> **★ 重点**：操作系统是计算机系统中最基本的系统软件，也是最接近硬件的一层软件。

- 计算机系统层次结构（自下而上）：裸机（纯硬件）→ 操作系统 → 应用程序 → 用户。操作系统处于硬件之上、应用软件之下。
- 裸机：不包含任何软件的纯硬件计算机（含 CPU、内存、硬盘、主板等）。在裸机上安装操作系统后，将其改造成功能更强、使用更方便的机器，这种覆盖了软件的机器称为扩充机器，又称虚拟机。

### 1.1.2 操作系统的功能与目标（三个视角）

- ①作为系统资源的管理者：管理处理机（CPU）、存储器（内存）、文件、设备四大资源。执行一个程序前必须先把它放入内存，才能被 CPU 处理。
- ②作为用户与硬件之间的接口（向上层提供方便易用的服务）：把“丑陋”的硬件功能封装成简单易用的服务（封装思想），用户无需关心底层硬件原理。
- ③作为最接近硬件的层次（实现对硬件机器的扩展）：将 CPU、内存、磁盘、显示器、键盘等硬件合理组织协调，实现更复杂的功能。

### 用户接口（三种）

| 接口类型 | 使用方式 | 举例/别名 |
| --- | --- | --- |
| 命令接口 | 用户直接使用，分联机与脱机两种 | 联机=交互式；脱机=批处理 |
| 程序接口 | 由一组系统调用组成，程序员通过代码间接使用 | 系统调用=广义指令 |
| 图形接口 GUI | 通过形象的图形界面操作 | 拖拽文件到回收站 |

- 联机命令接口（交互式命令接口）：用户说一句，系统做一句。如 cmd 中输入 time 命令。
- 脱机命令接口（批处理命令接口）：用户说一堆，系统做一堆。如 Windows 的 *.bat 批处理文件。
- 程序接口由系统调用组成，普通用户不能直接使用，只能通过程序代码间接使用（如 printf 底层就用到显示器相关的系统调用）。

> **★ 重点**：系统调用是应用程序请求操作系统服务的唯一方式，类似于函数调用。

## 1.2 操作系统的四个特征

### 1.2.1 并发

- 并发：指两个或多个事件在同一时间间隔内发生。宏观上同时发生，微观上交替发生。
- 并行：指两个或多个事件在同一时刻同时发生。并发与并行的本质区别：并发是“同一时间间隔”、并行是“同一时刻”。

> **★ 重点**：单核 CPU 同一时刻只能执行一个程序，各程序只能并发执行；多核 CPU 同一时刻可同时执行多个程序，可并行执行。

- 操作系统伴随着“多道程序技术”出现，操作系统与程序并发是一起诞生的；并发性是操作系统最基本的特性。

### 1.2.2 共享

- 共享即资源共享，指系统中的资源可供内存中多个并发执行的进程共同使用。分为互斥共享方式和同时共享方式。
- 互斥共享方式：一个时间段内只允许一个进程访问该资源。如摄像头同一时间段只能分配给 QQ 或微信其中一个进程。
- 同时共享方式：允许一个时间段内由多个进程“同时”访问。此“同时”往往是宏观上的，微观上可能交替访问（分时共享）。如 QQ 和微信同时读硬盘发送文件。

> **★ 重点**：并发与共享互为存在条件：失去并发性则共享无意义；失去共享性则无法实现并发。

### 1.2.3 虚拟

- 虚拟：指把一个物理上的实体变为若干个逻辑上的对应物。物理实体是实际存在的，逻辑对应物是用户感受到的。
- 时分复用技术（虚拟处理器技术）：单核 CPU 在微小时间段内交替为各进程服务，用户感觉有多个 CPU。
- 空分复用技术（虚拟存储器技术）：实际只有 4GB 内存，用户感觉内存远大于 4GB。

### 1.2.4 异步

- 异步：多道程序环境下允许多个程序并发执行，但由于资源有限，进程的执行不是一贯到底，而是走走停停，以不可预知的速度向前推进。

> **★ 重点**：没有并发和共享，就谈不上虚拟和异步，因此并发和共享是操作系统两个最基本的特征。

| 特征 | 含义 | 关键点 |
| --- | --- | --- |
| 并发 | 多个事件同一时间间隔内发生 | 宏观同时、微观交替 |
| 共享 | 资源供多个并发进程共同使用 | 互斥共享 + 同时共享 |
| 虚拟 | 一个物理实体变为多个逻辑对应物 | 时分复用 + 空分复用 |
| 异步 | 进程走走停停、速度不可预知 | 因资源有限而争抢 |

## 1.3 操作系统的发展与分类

- 手工操作阶段：用户独占全机，人机速度矛盾导致资源利用率极低。
- 单道批处理系统：引入脱机输入/输出技术（外围机 + 磁带），由监督程序控制作业输入输出（操作系统的雏形）。优点：缓解一定人机速度矛盾；缺点：内存仅能有一道程序，CPU 大量时间空闲等待 I/O，资源利用率仍低。
- 多道批处理系统：每次往内存读入多道程序，操作系统正式诞生，支持多道程序并发运行。优点：资源利用率大幅提升、系统吞吐量增大；缺点：用户响应时间长、无人机交互功能（无法调试、无法中途输入参数）。
- 分时操作系统：以时间片为单位轮流为各用户/作业服务，各用户通过终端交互。优点：用户请求可即时响应、解决人机交互问题、多用户相互独立；缺点：不能优先处理紧急任务（完全公平、不区分紧急性）。
- 实时操作系统：接到外部信号后及时处理，并在严格时限内完成，主要特点是及时性和可靠性。分硬实时（导弹控制、自动驾驶）与软实时（12306 订票系统）。优点：能优先响应紧急任务，不需时间片排队。
- 网络操作系统：伴随计算机网络诞生，实现数据传送、资源共享与计算机间通信（如 Windows NT）。
- 分布式操作系统：主要特点是分布性和并行性，各计算机地位相同，并行协同完成任务。
- 个人计算机操作系统：如 Windows XP、MacOS，方便个人使用。

| 发展阶段 | 主要解决问题 | 主要优点 | 主要缺点 |
| --- | --- | --- | --- |
| 手工操作 | 无 | 无 | 独占全机、利用率极低 |
| 单道批处理 | 缓解人机矛盾 | 一定程度提升利用率 | CPU 等待 I/O、利用率仍低 |
| 多道批处理 | 提高资源利用率 | 并发执行、吞吐量大 | 响应时间长、无人机交互 |
| 分时系统 | 人机交互 | 即时响应、多用户 | 不能优先处理紧急任务 |
| 实时系统 | 及时可靠响应 | 优先处理紧急任务 | 实现复杂 |

## 1.4 操作系统的运行机制

### 1.4.1 指令：特权指令 vs 非特权指令

- 指令是 CPU 能识别、执行的最基本命令（二进制机器指令）。一条高级语言代码翻译后可能对应多条机器指令。
- 特权指令：影响重大、只允许操作系统内核使用的指令，如内存清零指令。
- 非特权指令：应用程序只能使用的指令，如加法、减法指令。CPU 在设计生产时就划分了特权与非特权指令。

### 1.4.2 内核态 vs 用户态

> **★ 重点**：CPU 用程序状态字寄存器（PSW）中的某标志位区分状态：1 表示内核态（核心态/管态），0 表示用户态（目态）。

- 内核态：正在运行内核程序，可执行特权指令；用户态：正在运行应用程序，只能执行非特权指令。
- 内核程序：操作系统开发者（如微软、苹果）实现的程序，众多内核程序组成操作系统内核（Kernel），内核是最重要、最接近硬件的部分。

### 1.4.3 内核态与用户态的切换

> **★ 重点**：内核态 → 用户态：执行一条特权指令修改 PSW 标志位为“用户态”，意味着操作系统主动让出 CPU 使用权。

> **★ 重点**：用户态 → 内核态：由“中断”引发，硬件自动完成变态过程，触发中断信号意味着操作系统强行夺回 CPU 使用权。

- 一个程序在用户态执行特权指令属于非法事件，会引发中断信号，CPU 检测到中断后立即变为核心态，转去运行处理中断的内核程序。

## 1.5 中断和异常

### 1.5.1 中断的作用

> **★ 重点**：“中断”是让操作系统内核夺回 CPU 使用权的唯一途径。没有中断机制，就不可能实现操作系统，也不可能实现程序并发。

- 中断会使 CPU 由用户态变为内核态，使操作系统重新夺回对 CPU 的控制权；凡是需要操作系统介入的地方，都会触发中断信号。

### 1.5.2 中断的分类

| 分类 | 信号来源 | 与当前指令关系 | 例子 |
| --- | --- | --- | --- |
| 内中断（异常） | CPU 内部 | 与当前执行指令有关 | 非法指令、除 0、陷入 |
| 外中断（狭义中断） | CPU 外部 | 与当前执行指令无关 | 时钟中断、I/O 中断 |

- 内中断（异常）：来源于 CPU 内部、与当前执行的指令有关。如用户态执行特权指令、除数为 0、执行陷入指令。
- 外中断：来源于 CPU 外部、与当前执行的指令无关。如时钟中断（时钟部件每隔一个时间片发一次）、I/O 中断（输入输出任务完成时发送）。每一条指令执行结束时 CPU 都会例行检查是否有外中断信号。

### 1.5.3 内中断（异常）的再分类

| 异常类型 | 产生原因 | 内核处理方式 |
| --- | --- | --- |
| 陷入（trap/陷阱） | 由陷入指令故意引发（如系统调用） | 转去执行相应处理程序 |
| 故障（fault） | 错误条件引起，可被修复 | 修复后把 CPU 使用权还给应用程序继续执行 |
| 终止（abort） | 致命错误，无法修复 | 直接终止该应用程序，不归还 CPU |

- 故障例：缺页故障，内核修复后继续执行原程序。终止例：整数除 0、非法使用特权指令。

> **★ 重点**：大多数教材/试卷中，“中断”特指狭义的外中断，而内中断一般称为“异常”。

### 1.5.4 中断机制的基本原理

- 不同的中断信号由不同的中断处理程序处理。CPU 检测到中断信号后，根据中断信号的类型查询“中断向量表”，找到相应中断处理程序在内存中的存放位置。

> **★ 重点**：中断处理程序一定是内核程序，需要运行在内核态。

## 1.6 系统调用

### 1.6.1 系统调用与库函数的区别

- 系统调用：操作系统提供给应用程序（程序员）使用的接口，可理解为一种可供应用程序调用的特殊函数，用于请求内核服务。
- 库函数：编程语言向上层提供的函数，有时会将系统调用封装成库函数以隐藏细节、方便编程。

| 对比项 | 系统调用 | 库函数 |
| --- | --- | --- |
| 提供者 | 操作系统内核 | 编程语言/库 |
| 运行状态 | 处理在核心态 | 一般在用户态 |
| 是否必经 | 请求内核服务的唯一方式 | 不一定涉及系统调用 |
| 例子 | 创建文件 | 取绝对值（不涉及）；创建文件（涉及） |

### 1.6.2 什么功能要用系统调用

> **★ 重点**：凡是与共享资源有关的操作、会直接影响其他进程的操作，都必须通过系统调用请求内核完成，以保证系统稳定与安全。

- 常见需系统调用的功能：存储分配（内存）、I/O 操作、文件管理、进程控制、进程通信等。

### 1.6.3 系统调用的执行过程

- 传递系统调用参数（把参数放入通用寄存器）→ 执行陷入指令（用户态）→ 引发内中断使 CPU 进入核心态 → 执行相应的内核程序处理系统调用 → 返回应用程序。

> **★ 重点**：陷入指令是在用户态执行的，执行后立即引发内中断进入核心态；发出系统调用请求在用户态，而对系统调用的处理在核心态。

> **★ 重点**：陷入指令别名：trap 指令 = 访管指令。系统调用就是通过陷入指令完成的。

## 1.7 操作系统的体系结构

### 1.7.1 操作系统的内核

- 内核是操作系统最基本、最核心的部分。内核中包含：时钟管理（利用时钟中断实现计时）、中断处理、原语（设备驱动、CPU 切换等）、进程管理、存储器管理、设备管理等。

> **★ 重点**：原语是一种特殊程序，具有原子性：运行必须一气呵成、不可被中断。

> **★ 重点**：操作系统内核需要运行在内核态；非内核功能（如 GUI）运行在用户态。

### 1.7.2 大内核 vs 微内核

| 对比项 | 大内核（宏内核/单内核） | 微内核 |
| --- | --- | --- |
| 内核包含内容 | 进程/存储/设备管理 + 时钟、中断、原语 | 仅时钟、中断、原语、进程通信、调度等最核心功能 |
| 内核态/用户态划分 | 主要功能都在内核态 | 更多功能移到用户态 |
| 优点 | 各模块间直接通信、性能高 | 结构清晰、可靠安全、易扩展 |
| 缺点 | 结构庞大、可靠性低、难维护 | 频繁变态、性能开销大 |
| 典型系统 | Linux、UNIX | Windows NT |

- 变态过程是有成本的（消耗不少时间），频繁变态会降低系统性能。同一服务若同时涉及进程/存储/设备管理，大内核可能只需 2 次变态，微内核可能需 6 次变态。

### 1.7.3 其他结构（了解，考简单选择题）

- 分层结构：最底层是硬件，最高层是用户接口，每层只能调用更低一层，便于调试和验证，但层次间通信开销大。
- 模块化：按功能划分为多个模块，模块间通过接口通信，但模块间依赖关系复杂。
- 外核（exokernel）：把硬件资源的分配授权给应用程序直接管理，减少内核抽象开销，提高性能，但实现复杂、安全风险高。

## 1.8 操作系统引导（Boot）

- 引导（开机）过程：
1. ①CPU 从一个特定主存地址开始取指令，执行 ROM 中的引导程序（先进行硬件自检，再开机）。
1. ②将磁盘第一块——主引导记录（MBR）读入内存，执行磁盘引导程序，扫描分区表。
1. ③从活动分区（主分区，即安装操作系统的分区）读入分区引导记录（PBR），执行其中的程序。
1. ④从根目录下找到完整的操作系统初始化程序（即启动管理器）并执行，完成“开机”的一系列动作。

> **★ 重点**：引导顺序记忆：ROM 引导程序 → 主引导记录(MBR) → 分区引导记录(PBR) → 启动管理器/初始化程序。

## 1.9 虚拟机

- 虚拟机：使用虚拟化技术，将一台物理机器虚拟化为多台虚拟机器（VM），每台虚拟机都可独立运行一个操作系统。
- 虚拟机管理程序（VMM，同义：虚拟机监控程序 / Virtual Machine Monitor / Hypervisor）分为两类：

| 类型 | 运行位置 | 典型软件 |
| --- | --- | --- |
| 第一类 VMM | 直接运行在硬件上（裸机） | 服务器虚拟化产品 |
| 第二类 VMM | 运行在宿主操作系统之上 | VirtualBox、VMware |

- 支持虚拟化的 CPU 通常划分更多指令等级（Ring 0 为最高权限、Ring 3 为最低权限），以隔离客户机与 VMM。

## 经典例题

**【例题】** （特征判断）下列选项中，最能体现操作系统“并发性”的是：A. 多个程序在同一时刻同时运行；B. 多个程序在同一时间间隔内交替运行；C. 多个用户同时登录系统。

**解：** 选 B。并发指多个事件在同一时间间隔内发生，宏观同时、微观交替；A 描述的是并行，C 是分时系统的多用户特性，不直接等同于并发。

**【例题】** （中断分类）判断下列事件属于内中断还是外中断：①用户态执行特权指令；②时钟部件发来信号；③执行陷入指令；④键盘输入完成发来信号；⑤整数除 0。

**解：** ①内中断（终止）；②外中断（时钟中断）；③内中断（陷入）；④外中断（I/O 中断）；⑤内中断（终止）。判据：与当前执行指令有关且来源 CPU 内部为内中断，否则为外中断。

**【例题】** （系统调用过程）简述应用程序通过系统调用请求内核服务的完整步骤，并说明过程中 CPU 状态如何变化。

**解：** 步骤：①把系统调用参数放入通用寄存器（传参）；②执行陷入指令（trap/访管指令，在用户态执行）；③陷入指令引发内中断，CPU 由用户态自动切换为内核态；④转入系统调用入口程序，根据寄存器参数判断调用类型并执行相应内核处理程序；⑤处理完毕返回应用程序，CPU 由内核态变回用户态。要点：发出请求在用户态，处理在内核态。

**【例题】** （引导排序）请按正确顺序排列开机引导步骤：A. 执行启动管理器/初始化程序；B. 读入主引导记录；C. 执行 ROM 引导程序进行硬件自检；D. 读入分区引导记录。

**解：** 正确顺序为 C → B → D → A。即 ROM 引导程序（硬件自检）→ 主引导记录 MBR → 分区引导记录 PBR → 启动管理器。

**【例题】** （内核对比）大内核与微内核相比，下列哪项说法正确：A. 微内核性能更高；B. 大内核把更多功能放在内核态，性能更高但可靠性低；C. Windows NT 是大内核。

**解：** 选 B。大内核功能多在内核态，模块间直接通信，性能高但结构庞大、可靠性低；微内核结构清晰可靠但频繁变态、性能开销大；Windows NT 是典型微内核，Linux、UNIX 是典型大内核。

## 易错点速记

- “并发”是同一时间间隔（宏观同时、微观交替），“并行”是同一时刻，二者别混；单核只能并发，多核才可能并行。
- 并发与共享互为存在条件，且二者是最基本特征；没有并发和共享，就谈不上虚拟和异步。
- 虚拟 = 时分复用（虚拟处理器）+ 空分复用（虚拟存储器），不要漏记其中一种。
- “中断”在多数教材特指外中断，内中断叫“异常”；中断处理程序必为内核程序、运行在内核态。
- 内核态→用户态靠一条特权指令改 PSW；用户态→内核态靠“中断”，硬件自动完成，二者方向与手段不可颠倒。
- 陷入指令（trap=访管指令）在用户态执行，执行后引发内中断进入内核态；系统调用发出在用户态、处理在内核态。
- 原语具有原子性（不可被中断），不等于普通函数；操作系统内核运行在内核态，GUI 等非内核功能运行在用户态。
- 大内核典型是 Linux/UNIX，微内核典型是 Windows NT；微内核把更多功能放用户态，代价是频繁变态、性能下降。
